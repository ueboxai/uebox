# 混合团队设计（2026-10-24）

> 状态：方案，未动代码。依据 `main`（637d7b07）的代码阅读。
> 起因：第三期团队赛要让每个模型在自家客户端里跑——Fable 在 Claude Code（Claude 订阅）、Kimi 在 Kimi Code（会员）、Astra 在 Codex（ChatGPT 订阅），其余模型在盒子里——同时队员能力不能比盒子内 `/team` 差，也不要人在窗口之间转话。

## 1. 结论

- 盒子主进程当枢纽。团队状态、任务板、锁、快照、交付闸门都用现有的盒子内团队代码。
- 不用裸 WebSocket。外部客户端总得有东西在它那一侧启动和驱动模型，最后还是落到下面这几种驱动上。只有模型分散在多台机器上时，才值得在外面再包一层 WebSocket。
- 队员按「驱动」区分，接入点只有一个：`TeamToolDeps.runMember`（`teamTools.ts:99`，在 683 行调用）。它上面的排队、账本、用量、履历、自动快照、收件箱、任务板全部不动。

| 角色 | 跑在哪 | 怎么连 |
|---|---|---|
| 制作人 Fable | 官方交互式 Claude Code（用户自己登录） | 盒子 MCP（制作人精简工具集）；结果用 `team_wait` 取，或用 Claude Code Channels 推进会话 |
| 队员 · 盒子模型（DeepSeek、Grok、Qwen…） | 盒子 | 现有 `runSubAgent`，与 `/team` 完全一样 |
| 队员 · Kimi | Kimi Code CLI | 原生 ACP：`kimi acp` |
| 队员 · Astra | Codex | `codex app-server`（JSON-RPC over stdio） |
| 验收员 | Claude Code 里的 Fable 子 Agent（`uebox-acceptor`） | 盒子 MCP，验收员席位 |

## 2. 制作人在外、队员在盒子（第一阶段）

做法：在外部团队（`ext-*`）上加一个进程级的 `HybridTeamHost`（每队一个），把盒子内团队工具原样交给外部制作人。

- 队员不需要盒子的制作人回合。`runSubAgent(parent, {member})`（`createAgent.ts:1186-1433`）只要一个父 `SessionContext`，`hostSession.ts:133-163` 已经在为 MCP 调用方造这种上下文。
- 父上下文：`sessionId = teamId`；带 `team`、`pacedRequests`、工程、运行信息；**不带** `externalClient`（它会改提示词和工具）。思考档位、技能、MCP 和另外两队一致。
- `createTeamTools` 每队只建一次，`BusyMap` 跨 MCP 重连保留（MCP 会话 5 分钟无活动会被清掉，`McpServerHost.ts:73`）。
- 后台任务用宿主自己的中止控制器，Claude Code 取消一次调用不会杀掉跑到一半的队员。
- 工具在 `runWithTargetConnectionId(…, () => runWithEditorKey(fn))` 里执行，编辑器排队和盒子内一样；宿主存活期间挂编辑器看门狗。
- 队员写过东西就调 `registry.noteWrite`，作废之前的 PASS。

### 制作人的工具集（精简，约 6–9k token，首轮后走缓存；现在的完整工具集是 6–12 万）

| 工具 | 行为 |
|---|---|
| `team_open` | 建队，队员由盒子托管；返回席位、简报、接续信息 |
| `team_hire` | 盒子内版本，带 `model`、`model_reason`，过体检 |
| `team_send` | 一律后台派发；`wait:true` 时最多等约 8 分钟，否则提示用 `team_wait` |
| `team_wait`（新） | 有事件立刻返回，没有就最多等 600 秒；超时说明谁还在干 |
| `team_message`、`team_board`、`team_status`、`team_snapshot`、`team_dismiss` | 盒子内版本，不改 |
| `team_inbox`、`team_list`、`team_gate` | 现有 |

- 通过新请求头 `X-Unreal-Box-Profile` 选工具集（`McpSessionRequest`，`McpServerHost.ts:142-151`）。
- 制作人信箱代替盒子内的「插话」：`live.attach(PRODUCER, {steer: 进缓冲})`，队员交活、提问、崩溃通知都进缓冲，附在制作人每次工具调用的结果后面。

### 不让制作人自己动手

- 新插件 `packages/cli/claude-plugin-hybrid/`，只连一个带工具集请求头的盒子 MCP（不要再同时加载 `claude-plugin-mcp`，没进队的连接会放行所有写工具）。
- `PreToolUse` 钩子：拒绝 Write/Edit/MultiEdit/NotebookEdit；Bash 只允许 `uebox …`；子 Agent 只允许 `uebox-acceptor`。
- 启动时再加 `--disallowedTools "Write Edit MultiEdit NotebookEdit"`。
- Stop 钩子：还有后台任务或未读信件时，挡住并提示调 `team_wait`（不消耗催促次数，另设循环上限）；放行时调 `team_gate {phase:'stop'}`，宿主把制作人从信箱上摘掉。

### 验收

验收员用 Fable，跑在 Claude Code 的 `uebox-acceptor` 子 Agent 里。盒子内验收员用的是制作人自己的模型，另外两队也是自家模型验收，这样三队一致；盒子本身也调不了 Fable。验收提示词沿用 `buildAcceptancePrompt`，只读加试玩工具照旧限制。

## 3. 队员在自家客户端（第二阶段）

`runMember` 按队员的 `driver` 字段分流：`box`（现有）、`acp:kimi`、`codex-app-server`。`TeamMember` 上加 `driver`，招人参数里加对应选项。

每个外部驱动要做到：

1. **工具走盒子**：给客户端一条盒子 MCP 连接，绑定这个队员的席位（外部团队的席位机制，`externalTeamTools.ts:245, 392-444`）。锁、编辑器排队、角色限制、写操作账本照常生效。任务结束把席位账本拷回，自动快照才能跑。
2. **记忆**：客户端自己保留会话。团队存储里记每个队员的会话 ID，每个任务续上同一个会话（Kimi `session/load`，Codex `thread/resume`）。
3. **插话**：Codex app-server 有 `turn/steer`，能插进正在跑的回合；ACP 只能等回合结束再发，插不了的就走收件箱。
4. **进度、结果、用量、取消**：客户端事件转成 `onProgress`（进任务板）、最终回复当结果、token 事件记用量、取消映射到客户端的取消。
5. **体检和降级**：招人体检改成「拉起客户端，调一次盒子工具」；客户端挂了是降级到盒子模型还是直接判任务失败，要定一个。

另外，盒子能拿到外部模型自己写的文字，可以显示在实时活动面板上，录屏就有内容。

## 4. 订阅和条款

- **Claude**：Anthropic 允许个人用自己的订阅登录官方 Claude Code；不允许通过 Agent SDK 用订阅凭据替别人跑。所以制作人用**用户自己打开的交互式 Claude Code**，结果用 `team_wait` 取或用 Channels 推。不用 `claude-agent-acp`（基于 Agent SDK，部分集成已经禁止订阅登录），也不在公开版盒子里做「用 Claude 订阅驱动」的功能。
- **Codex**：app-server 用 ChatGPT 登录，本机自用可以；文档写明不能用于商业或托管服务，不能做成盒子的公开功能。
- **Kimi**：`kimi acp` 是官方给 IDE 用的方式，会员登录一次即可；Kimi 已宣布会员和 Kimi Code 订阅要拆分，到时可能有变。

结论：混合团队的「订阅驱动」部分只用于节目录制，不进公开版。

## 5. 风险和待确认

- Claude Code 调 MCP 工具的超时上限（`MCP_TOOL_TIMEOUT`），`team_wait` 要等多久要按这个定。
- MCP 会话被清掉（404）后 Claude Code 会不会重新初始化。
- 制作人空闲时队员发提问，没有 Stop 钩子摘信箱的话要等满 10 分钟。
- 队员模型挂掉时降级到盒子默认模型，提示文字却写「换成你的模型」（`teamModels.ts:132`、`teamTools.ts:815`），要改。
- 几份订阅并行可能撞限流。
- Channels 是预览功能；codex-acp、app-server 的 WebSocket 是实验性的。
- Windows 上子进程崩溃后的清理。
- Fable 的用量盒子看不见，除非 Stop 钩子去读 Claude Code 的会话记录。
- 公平性：Fable 保留 Claude Code 自带的读文件和联网工具。

## 6. 里程碑

**第一阶段（制作人在外，队员在盒子），不需要 Unreal 工程就能测：**

- 做：工具集请求头和精简工具集；`team_open` 建盒子托管队员；hire/send/wait/board/status/message；宿主（自动审批、信箱）；外部团队页显示实时状态和用量。
- 测：Fable 在 Claude Code 里招 DeepSeek V4.1 Flash 当策划，写一份设计文档，在任务板上放 3 个任务。
- 期望：体检跑了、招人理由显示在任务板上；`team_wait` 拿到结果；任务板显示模型、任务、用量、运行中；第二个任务能看出队员记得第一个；任务进行中发 `team_message` 能实时插进去。

**第二阶段**：Unreal 实际干活、验收员和闸门、PreToolUse 守卫、接续信息、任务板上换模型和解雇、审批界面。

**第三阶段**：Kimi（`kimi acp`）和 Codex（`codex app-server`）外部驱动。
