# 技能方法论审计（2026-10-14）

起因：对照一份外部 UE 性能排查做法，发现 `ue-project-audit` 的性能排查漏掉了「运行时开关做减法」这一层，测量纪律也不全。于是用同样的标准把其余 UE 技能查了一遍：业内专家怎么做、我们的技能怎么写的、我们的工具到底能不能做到。

范围：21 个 UE 相关技能。通用技能（研究、知识库、出图等）不涉及 UE 专业方法，没有纳入。审计全程只读。

## 写得扎实、不用动的

- **ue-sequencer**：帧边界、possessable/spawnable、warm-up、黑屏排查顺序都到了专家水平。它是唯一做过多位资深用户评审的技能。
- **ue-editor-inspection**、**blender-ue-pipeline**、**ue-material-substrate**、**ue-landscape**：没有值得列的缺口。
- **ue-level-organize**、**ue-ai-render-from-blockout**：基本没问题。

## 五类毛病

| 类 | 大白话 | 涉及条目 |
|---|---|---|
| A 只做不验 | 做完就报完成，没在真正运行的状态下确认效果 | C2, B2, R1, R2, I1, I3, U1, U2 |
| B 下手太重 | 先用了贵的、不可撤回的办法，跳过了便宜、可撤回的 | P1, G1, M3, PCG1 |
| C 只看自己 | 只检查改的那一处，不看会牵连到谁 | B1, A1, C3, D3 |
| D 尺子拿错 | 用错误的指标下结论 | M1, M2, U3, D1, MAT1 |
| E 工具缺口 | 专家的步骤我们的工具做不到，要改盒子或插件 | X1–X6 |

## 缺陷清单

「成本」一栏：文档 = 只改技能文档；盒子 = 改盒子工具；插件 = 改 UE 插件。

### 性能排查（ue-project-audit，前一轮已讨论）

- **P1 [B] 没有运行时开关减法这一层**：从瓶颈分级直接跳到「复制关卡、删资产」。成本：文档。
- **P2 [A] 测量纪律不全**：不丢预热数据、不重复测量看噪声、不交替 A/B、不重置会跨 PIE 残留的设置。成本：文档；预热参数和设置自动还原要改盒子和插件。
- **P3 [C] 不统计灯光**：投影灯数量、半径，以及半径内的可移动物体和 WPO，都没有工具能查。成本：盒子 + 插件。

### C++ 与诊断（ue-cpp-workflow / ue-system-diagnostics）

- **C1 [B] 不区分哪些改动能热补**：改了头文件里的反射结构或构造函数默认值，必须关编辑器重编；技能只在崩了之后才提（`ue-cpp-workflow/SKILL.md:59-60,93`）。`needs_full_rebuild` 不看头文件（`compile.ts:125-141`）。成本：文档；也可以让盒子检测头文件改动。
- **C2 [A] 编过就算完**：没有「重开 PIE 看行为」这一步；不知道构造函数默认值不会覆盖已放置的实例；`ue_playtest` 不收 Log 级日志。成本：文档。
- **C3 [C] 不教先修第一条错误；没有链接错误对照**：`LNK2019` 的常见原因是 `.Build.cs` 少了依赖、类没有 `XXX_API` 导出。成本：文档。
- **D1 [D] 指错日志**：让模型去 Message Log 找命令输出，其实应该看 `Saved/Logs`（`ue-system-diagnostics/SKILL.md:60-61`）。插件提示文字也写错了（`UAL_SystemCommands.cpp:284-285`）。成本：文档 + 插件一句话。
- **D2 [A] 不会读调用栈**：没教看崩溃类型、找第一帧属于项目自己的代码，以及缺调试符号时不能瞎猜。成本：文档。
- **D3 [C] 拿不到崩溃前的日志，也不分崩溃类型**：ensure 和卡顿被当成崩溃（`getCrashLogs.ts:257-279,342`）。仓库里 `services/editorCrashWatch/crashReport.ts:50-74` 已经有过滤逻辑，可以复用。成本：盒子。
- **D4 [A] 开发时全绿、打包时全红**：没给验证手段；`cpp_full_rebuild` 写死只编 Editor 目标。成本：盒子。
- **D5 [A] 没有「复现 → 缩小范围 → 修完再复现」这条流程**。成本：文档。

### 蓝图、摆放、UMG

- **B1 [C] 改变量或签名、换父类前不查引用方**：只编当前蓝图；`blueprint_compile_all` 默认只编插件自己改过的（`compileAllBlueprints.ts:36-42`）。成本：文档。
- **B2 [A] 「逻辑不触发」没有排查流程**：不教一次在多处埋打印点；没写重叠需要双方碰撞通道对上、非 Pawn 收输入要 EnableInput 这些常见原因。成本：文档。
- **A1 [C] 删 Actor 前不查谁在引用它**：插件直接调 `EditorDestroyActor`（`UAL_ActorCommands.cpp:583`），跳过了编辑器自带的引用警告。成本：插件。
- **A2 [A] 没提 Mobility**：运行时要动的东西必须设成 Movable，否则门不动、只在日志里留一条警告。成本：文档。
- **U1 [A] UMG 没讲怎么让控件在游戏里显示**：CreateWidget → AddToViewport、输入模式这几步都没写；具名节点里也没有 CreateWidget（`UAL_BlueprintCommands.cpp:4570`）。成本：文档；要稳的话插件加具名节点。
- **U2 [A] 联机复制无法验证**：`ue_playtest` 只跑单进程，没有网络模式和客户端数量参数。成本：文档先写明需要用户自己测；根治要改插件。
- **U3 [D] 多分辨率预览不套用 DPI 缩放**：预览出的图和游戏里对不上（`UAL_WidgetCommands.cpp:1073`）。应该改成固定高度、只变宽度来测宽高比。成本：文档；插件可以补上缩放参数。

### 材质、PCG、几何、资产体检

- **MAT1 [D] 「受击闪白」被引向 MPC**：MPC 是全局的，打一个会全体一起闪。文档还写错了，说实例参数运行时不能改（`ue-material-authoring/references/reuse-and-scale.md:5,14,40-41`）。成本：文档。
- **MAT2 [A] 不看材质开销**：指令数、采样器数、静态开关排列都不看；`material_compile` 不返回统计数据。成本：插件（小）。
- **PCG1 [B] 没有规模预算**：不估算实例数、不先在小范围试跑、不设剔除距离。成本：文档。
- **PCG2 [A] 不讲种子和分布质量**：没提 Seed、Self Pruning、坡度过滤。成本：文档。
- **G1 [B] 「面数太高」直接对 LOD0 破坏性减面**：没先考虑 Nanite 和自动 LOD（`ue-geometry-editing/SKILL.md:130`）。成本：文档。
- **G2 [A] 布尔挖洞后，副本沿用旧的碰撞和导入的 LOD**：结果是门洞走不过去、远处切 LOD 后洞消失。成本：文档。
- **M1 [D] 体检按原始面数排名，不区分 Nanite**：判定代码不检查 nanite（`levelFindings.ts:121-135`）。成本：文档 + 盒子（小）。
- **M2 [D] 包体和内存问题按磁盘大小排**：不先排除没人引用的资产；建议重新导入来降尺寸，而不是用 LODGroup / MaxTextureSize。成本：文档。

### 导入、重定向、AI 3D

- **R1 [A] 重定向只在静态姿势上验**：不播 walk/run 看滑步、陷地和根运动（`ue-animation-retargeting/SKILL.md:38-46`）。`anim_measure` 已经能取逐帧骨骼坐标。成本：文档。
- **R2 [A] 出片后不看帧**：不抽看首帧和切点帧；推荐用来预览的 draft 档没有预热（`UAL_RenderCommands.cpp:104`）。成本：文档；可选插件。
- **I1 [A] 网格导入后没有验收清单**：尺寸、轴心、碰撞、光照贴图 UV、Nanite、导入警告都不查；`mesh_describe` 其实一次就能读全。成本：文档。
- **I2 [D] 贴图通道识别不全**：认不出 ORM/ARM 合并贴图，会保持 sRGB 开；不处理 OpenGL 法线的绿通道翻转；`bump` 被误当成法线（`UAL_PBRMaterialHelper.cpp:63-140,491-505`）。成本：文档先止血；根治要改插件。
- **I3 [A] AI 3D 资产只对面数预算**：没检查真实尺寸、轴心、基础色里烘死的光影、UV 和 Nanite。成本：文档 + 计划模板。
- **R3 [E] MRQ 不能加控制台变量**：治不了首帧贴图糊、LOD 跳变。成本：盒子 + 插件。

### 工具缺口汇总（E 类）

- **X1** 控制台命令写死在编辑器世界执行（`UAL_SystemCommands.cpp:258`）。全局变量（`r.*`、`ShowFlag.*`）不受影响；依赖世界的命令（`dumpticks`、`show`、对象查询）在 PIE 跑着时查错了对象。
- **X2** 采样工具没有预热参数，也不会自动还原改过的设置（P2）。
- **X3** PIE 不能开监听服务器加多客户端（U2）。
- **X4** 材质编译不返回统计数据（MAT2）。
- **X5** 崩溃工具不分类型、拿不到崩溃前日志（D3）。
- **X6** MRQ 不能加控制台变量（R3）。

## 根因

`resources/skills/SKILL_STANDARD.md` 只规定了结构、触发条件和篇幅，没有要求写清「怎么验证」「先做哪些便宜的、可撤回的检查」「会牵连到谁」，也没有领域专家评审这一步。唯一做过专家评审的 ue-sequencer，正好是这次最扎实的一个。

### 第三轮

- C1：`cpp_compile` 回执带 `reflected_headers_changed`（开编前比上次产物新、带 GENERATED_BODY 的头文件）。只报事实；
  「改的是不是反射布局」仍由模型对照技能里的分类表判断——Live Coding 能补到什么随版本和设置变，工具下不了可靠结论。
- LOD 生成、简单碰撞、凸包分解：新工具 `mesh_optimize`（按需组 `ue.mesh.optimize`），导入的 LOD 默认不动，
  `keep_imported` 保留、`replace_imported` 在用户同意后替换。
- 「哪些蓝图用了某个 C++ 成员」：新工具 `blueprint_find_usages`（按需组 `ue.blueprint.usages`），
  插件 `blueprint.find_in_blueprints`。它是编辑器「在所有蓝图中查找」的薄封装：直接驱动引擎的
  `FStreamSearch`（Kismet，`FindInBlueprintManager.h`），不加载蓝图、不另建索引；在搜索线程上跑，
  插件每帧取一次结果，60 秒超时交出部分结果。回执带覆盖情况（未索引 / 索引过期 / 索引失败），
  不全时摘要单列一行；`index_unindexed: true` 请编辑器弹它自己的 Index All 确认框（5.4+ 尊重
  `AllowIndexAllBlueprints` 开关）。`ue-cpp-workflow` 的波及面一节和 `ue-blueprint-graph-editing` 的
  「Changing what others already use」改为先查它、改完照旧编译受影响的蓝图。
  与 `docs/UE项目索引设计-2026-10-14.md` 的关系：那边第三期「蓝图内容档 + 桥」要解 FiBData 建档、
  回答「谁调用了」；建档前这个工具就是现问编辑器的那条路，建档后它可以做档案缺失时的回退，
  两者用的是同一份引擎数据，不是两套索引。
