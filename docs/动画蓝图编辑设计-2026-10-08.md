# 动画蓝图编辑设计

> 状态：已实现，一次做完不分期 · 2026-10-08

## 一句话

不加新工具。现有的「读图 / 写图 / 新建蓝图 / 搜节点」四个工具认识动画蓝图：能读懂、能改 AnimGraph、状态机、状态内部和转换条件，能新建动画蓝图。

## 为什么要做（大白话）

普通蓝图是一张平面电路图；动画蓝图是一本**套娃图册**：

- 第一页 AnimGraph，一条「姿势流水线」，最后流到「输出姿势」。
- 流水线里的「状态机」节点，点进去是另一页：状态（站立、走、跑）和它们之间的箭头。
- 每个状态点进去又是一页：这个状态播什么动画。
- 每根箭头点进去还有一页：什么条件下跳过去（比如速度 > 10）。

以前 Agent 只认第一页、不认识动画零件、零件放上去调不了、连册子都建不出来。

## 怎么做的

### 用「路径」翻到任意一页

| graph_name | 是哪页 |
|---|---|
| `AnimGraph` | 姿势流水线 |
| `AnimGraph/Locomotion` | 名叫 Locomotion 的状态机 |
| `AnimGraph/Locomotion/Idle` | Idle 状态里面 |
| `AnimGraph/Locomotion/Idle->Walk` | Idle 跳到 Walk 的条件 |
| `AnimGraph/Locomotion/Idle->Walk/CustomBlend` | 这条转换的自定义混合（LogicType 设成 Custom 后才有） |

转换规则图的对象名是引擎自动起的（Transition_3），只能按两端状态名认；同一对状态之间多条转换时第二条起写 `Idle->Walk#2`。普通蓝图的折叠图也顺带能按路径进去。读写回执里的 `graph_name` 一律回路径，抄回来就能用。

### 姿势图、状态内部、转换规则：照常整图写

这几页都是蓝图图（动画的 schema 派生自蓝图的），现有的整图写入照常走，加了三件事：

- **动画节点叫名字**：`OutputPose`（每页自带，只复用）、`SequencePlayer` / `BlendSpacePlayer` / `AimOffset`（member_name = 动画资产）、`StateMachine`（member_name = 名字，同名的复用不重建）、`SaveCachedPose` / `UseCachedPose`（member_name = 缓存名）、`BlendPosesByEnum`（member_name = 枚举，每项自动加一个输入）。别的动画节点写类名去掉 `AnimGraphNode_` 前缀即可。
- **`settings`**：节点细节面板里那些，按属性名写，插件用反射写进节点的设置结构体。露成引脚的值写到引脚上（引擎以引脚为准）。数组写到第 N 个时，先用引擎自己的「加引脚」把并排的几个数组一起加长 —— 只撑长一个数组节点就坏了。
- **藏着的引脚按需变出来**：连线或 pin_defaults 点名了 `PlayRate`、`BlendPose_3` 这类默认藏着 / 还不存在的引脚，就暴露 / 补输入。必须在解析任何一根线之前统一做完：暴露引脚会重建节点的全部引脚，边解析边暴露会留下野指针（真机上崩过一次）。

转换规则里另有 `TransitionGetter`：读离开的那个状态里动画播到哪了（TimeRemainingRatio 等）。那个状态里有多个播放节点时按资产名点名，同一段动画放了两个时按节点 GUID。

### 状态机那一页：节点是状态，线是转换

单独一个写入入口（同一条命令，打到状态机图上时转过去）：

- 节点只收 State / Conduit / StateAlias，member_name 是名字，**同名复用**。
- 连线两端写请求里的 id、已有状态名或 `Entry`；同一对状态之间已有转换就**原地改**，不叠一条。
- 连线可以带 `settings`（混合时长、优先级、LogicType……）。
- 全有或全无：任何一条错就整批回滚，复用节点上改过的设置、入口连线、别名指向一起写回去。

### 新建动画蓝图

`blueprint_create` 父类填 AnimInstance 时走引擎自己的动画蓝图工厂，`skeleton` 必填（骨架或骨骼网格体，路径或名字都行）。不给就报错并列出项目里的骨架。

### 编译报错指回页面

诊断带上 `graph`（节点所在那一页的路径）。`clear_existing` 删掉一个还被别的转换规则读着的播放节点或状态时，回执里直接说哪条规则会坏 —— 引擎事后的报错只有一句看不出来源的「ICE: Player node … was not processed」。

## 名词表

| 名词 | 含义 |
|---|---|
| AnimGraph | 动画蓝图里算出每帧最终姿势的主图 |
| 状态机 | AnimGraph 里的一个节点，里面是状态和转换 |
| 转换条件 | 状态 A 切到 B 的判断，本质是一张返回布尔值的小图 |
| `settings` | 动画节点 / 状态 / 转换的设置项，按属性名填 |
| 图路径 | 用 `/` 和 `->` 定位到任意一页的写法 |

## 增减计数

| | 改前 | 改后 |
|---|---|---|
| Agent 看到的蓝图工具数 | 不变 | 不变 |
| 写图节点字段 | class / member_name / pin_defaults … | 多 `settings`；StateAlias 专用 `aliased_states` / `global_alias` |
| 写图连线字段 | from / to | 多 `settings`（只在状态机页） |
| 新建蓝图参数 | 现有 | 多可选的 `skeleton` |
| 新概念 | — | 图路径（1 个） |

## 默认可见 / 按需出现

- **默认可见**：写图工具描述末尾一段四行的「动画蓝图」；读图描述一段。
- **按需出现**：详细写法在技能 `ue-blueprint-graph-editing` 的 `references/anim-blueprints.md`；动画节点名单只在搜索动画蓝图时出现在 `anim_nodes`；状态机页的规则、取值节点的写法随报错一起返回。做普通蓝图的 Agent 看不到这些。

## 不在范围内

都是 AnimGraph 之外的独立资产：Control Rig / IK Rig 资产本身、Pose Search 数据库、蒙太奇和动画通知的编辑。（AnimGraph 里的 Control Rig 节点、Motion Matching 节点、动画层节点照常能放 —— 它们只是动画节点。）

- 插件：`Private/Commands/UAL_AnimGraphSupport.{h,cpp}`（路径、动画节点、设置、状态机页、新建、搜索），`Public/Utils/UAL_AnimGraphNames.h`（纯字符串部分，有自动化测试 `UnrealAgentLink.Blueprint.AnimGraphNames`）。`UAL_BlueprintCommands.cpp` 里的找图、建节点、整图写入、读图、列图、新建、搜索调进来。依赖加了引擎本体模块 `AnimGraph`、`AnimGraphRuntime`。
- 引擎接口：动画图编辑器里很多类在新版本是 MinimalAPI，只用数据成员、虚函数、StaticClass 和 5.0 / 5.8 两头都导出的函数（`CreateConnections`、`GetPreviousState`、`AddPinToBlendList` 等）；private / protected 的 UPROPERTY 走反射。
- 应用：`applyBlueprintGraph.ts`、`getBlueprintGraph.ts`、`createBlueprint.ts`、`searchBlueprintNodes.ts`、`describeBlueprint.ts`。
- 真机验证（5.8 宿主工程）：新建、AnimGraph、状态机、状态内部、转换规则、取值节点、按需暴露引脚、按需加输入、枚举混合、分层混合、IK 自动插空间转换、整批回滚（新建和复用两种）、整页重写、删除状态、读引擎自带的动画蓝图。
