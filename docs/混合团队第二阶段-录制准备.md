# 混合团队第二阶段：录制前准备和开机步骤

对应设计稿 `docs/混合团队设计-2026-10-24.md` 第 2、6 节第二阶段。Fable 在官方 Claude Code 里当制作人，队员在盒子里跑，
验收员是 Claude Code 里的 `uebox-acceptor` 子 Agent。第一阶段的测试步骤见 `docs/混合团队第一阶段-手动测试.md`。

## 一次性准备

1. 盒子用这个分支出的版本（合并后正式版或 dev 盒子都行）。
2. 设置 → AI：把要招的队员模型都配好。
3. 设置 → MCP → 共享引擎能力：打开，允许写操作。记下令牌。
4. `uebox` 命令行用这个分支的代码重新编一次（三个 hook 都靠它）：

   ```bash
   pnpm --dir packages/cli build
   ```

   `uebox --version` 能跑就对了。
5. 环境变量，两个都设（用户级环境变量，设完重开终端）：
   - `UEBOX_TOKEN` = 第 3 步的令牌
   - `UEBOX_URL` = `http://127.0.0.1:17861/`
   - 可选：`CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT` = `660000`（`team_wait` 一次等满 10 分钟；不设也行，默认每次等 280 秒）
6. 工程：用来比赛的模板工程先在盒子「项目库」里登记好（Fab 下载的模板也行）。不用新建，制作人用 `open_project` 打开它。

## 每次开录

1. 开盒子，打开「外部团队」页。
2. 二选一：
   - **桌面版 Claude 的 Code**（不用装命令行）：新建会话，工作目录选准备好的文件夹（例如 `I:\UEBox Project\Feble`，
     里面放 `.mcp.json`、`.claude/settings.json`、`.claude/agents/uebox-acceptor.md`，内容同插件；`.mcp.json` 里直接写
     令牌和地址，不要写 `${…}`）。权限模式选 Bypass permissions，盒子工具不会停下来问；`settings.json` 里也放了
     `permissions.allow: ["mcp__uebox-producer__*", "mcp__uebox-acceptor__*"]`。
   - **命令行**：在空文件夹里

     ```bash
     claude --plugin-dir H:\UnrealAgent\uebox-pub\packages\cli\claude-plugin-hybrid --permission-mode bypassPermissions
     ```

     bypass 下 hook 照样生效。要 Fable 只协调不动手，再加 `--disallowedTools "Write Edit MultiEdit NotebookEdit"`。
     这次比赛 Fable 允许自己写文件：命令行那条路要去掉插件里的守卫 hook，桌面版那份配置里已经没有它。

3. 模型选 Fable。MCP 里只有 `uebox-producer`（16 个工具），状态是已连接。
4. 第一句话给 Fable（按队伍改）：

   ```text
   用虚幻盒子的混合团队做：<一句话目标>。
   工程用 <工程路径>，用 project_manage 的 open_project 打开，不要新建。
   开团队时 thinking_level 填 <和另外两队一样的档位>。你也可以自己动手改。
   队员用这几个模型：<模型 id 列表>。
   ```

5. 盒子那边：「外部团队」页能看到队员、模型、在干的活、用量。

## 审批：团队模式一律全放行

三队同一个规矩：队员每一步由模型自己判断，盒子不弹确认框，也不发给制作人批。

- 混合团队（Fable 队）默认 `approval_mode: yolo`。
- 盒子里的 `/team`（另外两队）在团队模式下自动按「全部权限」跑，输入框里的档位不影响团队。

整个跑下来盒子不弹需要你点的东西：队员没有 `ask_user`，也不会弹换工程、确认工程的框；验收员不过审批。

想让制作人把关不可逆的操作，混合团队开团队时 `approval_mode` 填 `producer`：那几步以 `[team approval …]` 消息发给制作人，
用 `team_approve` 准或不准，10 分钟没答复按不准处理。填 `auto-edit` / `ask` 则在盒子窗口弹框问你。

## 会看到的自动行为

- Fable 想收尾时：队员还在干活或有话没看，Stop hook 让它 `team_wait`；没过验收，提醒它起 `uebox-acceptor`，每轮最多提醒两次。
- 验收 PASS 之后队员再改工程，PASS 作废，Stop hook 会再次要求验收。
- 你每发一句话，这句话会记给验收员；任务板上上一轮没动的旧账会加进 Fable 的上下文。
- 编辑器崩了盒子自动重开，Fable 下一次调团队工具时会看到经过。
- 装了守卫 hook 时（命令行插件那条路），Fable 想改文件、跑别的命令、起别的子 Agent，会被拒绝并告知原因。

## 收工

「外部团队」页点「结束团队模式」：后台还在跑的活停下，编辑器看护停掉，Fable 再调工具会被告知团队已结束。

## 2026-10-24 联调结果（dev 盒子 + 脚本代替 Fable + 真模型 + 一次性 UE 5.6 工程）

通过：开已有工程并自动记成团队工程、编辑器写操作（放 Actor、改变换、存盘、快照）、编辑器崩溃自动重开并通知、
auto-edit 下删除 Actor 弹确认框并在确认后继续、验收员以普通连接进门（只读，写操作被拒）、PASS 后队员写工程作废 PASS、
Stop hook 的「等队员」和「没验收」两种拦法、新一轮记下用户那句话、任务板上换模型（体检后下一件活生效）和辞人、结束团队后宿主和看护都停。

没测成或没测：

- 打包：`project_package` 被 Live Coding 挡住（编辑器开着，加上引擎级插件让纯蓝图工程也走编译）。录制前先在目标工程上手动打一次包确认能过；不行就让队员关掉 Live Coding 或在编辑器关着时打包。
- 真的 Claude Code + Fable：订阅只能在官方交互式 Claude Code 里用，这里用脚本代替。插件里的 hook、子 Agent 内联 MCP、`${UEBOX_TOKEN}` 展开要在录制前跑一遍。
- 资产锁：任务板「谁占着哪些资产」能看到队员占着当前关卡，但两个队员这次的写没有撞上，锁是否拦下并发写没看到。
