# 连接虚幻引擎

正常情况下你什么都不用做：导入工程时插件自动装好，编辑器一开就自己连上。

这页讲三种情况：连不上、装不上、不想让它装。

Agent 查关卡、改属性、跑 PIE，都通过装在你工程里的插件 **UnrealAgentLink** 完成。没有它，Agent 够不着引擎，只能聊天。

## 它怎么装上的

**默认全自动。** 装的位置是 `<工程>/Plugins/UnrealAgentLink/`，**不是引擎目录**。

一次安装做四件事：

1. 把对应引擎版本的插件解压到工程的 `Plugins/UnrealAgentLink/`
2. 清掉同一引擎下早期版本留在引擎目录里的残留
3. 往 `.uproject` 的插件列表里加上它并置为启用
4. 往 `.gitignore` / `.p4ignore` 各加一行 `Plugins/UnrealAgentLink/`

::: tip 第 4 步是为了不把它提交进版本库
插件是盒子装的，不是你工程的一部分，也会随盒子升级换版本。忽略掉它，团队里没装盒子的人不会被这个目录干扰。
:::

触发时机有三个：

- **导入工程时**
- **每次启动应用时**：遍历已导入的工程，版本落后就静默升级
- **Agent 发现插件太旧或没装上时**：见[插件太旧或没装上时 Agent 自己处理](#插件太旧或没装上时-agent-自己处理)

支持 **UE 5.0 到 5.8**，正式安装包里九个版本的插件都在。

::: tip 为什么正式包要带九份
少一个版本，那个版本的用户就会装到旧插件。所以打正式包的门禁要求 5.0–5.8 全部存在，并且与源码一致。
:::

### 为什么装到工程而不是引擎

三条原因：

| 原因                 | 具体是什么                                                                       |
| -------------------- | -------------------------------------------------------------------------------- |
| **权限**             | Launcher 装的引擎在 `C:\Program Files` 下，非管理员写不进去；工程目录永远可写    |
| **构建缓存**         | 引擎目录下的插件会被编进引擎级的构建规则缓存，反复装卸容易把它搅浑，报错难以归因 |
| **没有版本匹配机制** | Epic 自家插件敢装引擎级，是因为 Launcher 会按你的引擎版本推送对应构建            |

### 随包带的是源码 + 预编译

带二进制，你不用自己编译。**同时带源码**，是为了自编译引擎也能用：自编译引擎每次编译的构建标识都不同，对不上预编译的二进制，有源码时引擎会当场重编一遍，不需要你操作。

插件源码在仓库的 `plugin/UnrealAgentLink`，用的是独立的 **MIT 许可证**，想自己编就自己编。

## 不想让它自动装

**设置 → 插件 → 关掉「自动安装连接插件」。**

单个工程不想要：工程卡片右键 → **移除桥接插件**，在确认框里确认。这会删掉那个工程下的 `Plugins/UnrealAgentLink` 目录、从 `.uproject` 里摘掉它，并把这个工程记进一份**不再自动安装**的名单。

::: tip 为什么要用右键菜单移除
手动删除插件目录没用：盒子把「文件不存在」当作「需要安装」，下次打开工程会原样装回来。从右键菜单移除才会写入名单，之后导入时、启动时的自动安装都会跳过这个工程。

想装回来就右键 →「安装桥接插件」，盒子会先把这个工程移出名单。
:::

Agent 自动安装插件时也会跳过名单里的工程，只有你明确要求装回来才会装。

## 确认连上了

**设置 → 插件 → 连接状态**：

![设置 → 插件：连接状态](/shots/settings-plugin.png)

| 显示             | 含义                                |
| ---------------- | ----------------------------------- |
| 引擎桥接：正常   | 应用已在端口 `17860` 上等待引擎接入 |
| 引擎桥接：未运行 | 桥接没运行，引擎连不进来            |
| 引擎桥接：读取中 | 还在问状态                          |
| 已连接的工程：N  | 当前有 N 个编辑器接上了             |

::: tip 不需要手动连接
插件会自己连过来，断了每 5 秒重试一次。

![连上之后：引擎桥接「正常」，已连接的工程为 1](/shots/settings-plugin-connected.png)

**工程明明开着，「已连接的工程」却一直是 0** —— 最常见的原因是那个工程没装插件。回项目库，工程卡片右键 →「安装桥接插件」。
:::

状态还没读到时显示「正在读取桥接状态…」，不会误报「未运行」。

桥接起不来时，主界面会挂一条横幅：「引擎桥接启动失败」。

## 编辑器状态与崩溃

连上之后，盒子还会盯着编辑器的状态。

**状态监控。** 对话页顶栏的「状态监控」读取插件上报的编辑器指标，每项旁边写预期值，偏离预期的项排在「需要注意」里，旁边有「问 AI」按钮，点一下就把这项数据发给 Agent 排查。

| 分组        | 指标                                                       |
| ----------- | ---------------------------------------------------------- |
| 编辑器      | 打开编辑器耗时、资产注册表扫描、已启用插件数、编辑器卡顿率 |
| 试玩（PIE） | 首次进入、最近一次进入、PIE 卡顿率                         |
| 缓存        | 本地缓存命中、本地缓存占盘                                 |
| 内存        | 可用内存                                                   |

预期值照搬虚幻编辑器自带「编辑器诊断」窗口的默认值。个别指标在较低的引擎版本上读不到，显示「此版本不提供」。工程里的插件太旧时，面板提示更新插件。

**崩溃恢复。** Agent 的命令在等结果时编辑器崩溃，盒子会确认进程已崩溃，并告诉 Agent 原因，由 Agent 决定要不要重开。重开时盒子会关掉崩溃报告窗口，把未保存的自动存档备份到工程的 `Saved/UEBoxCrashRecovery`，再重新打开工程。5 分钟内再崩一次就不再重开。你自己操作时发生的崩溃不会触发重开。

**设置 → 插件 →「允许 Agent 重开崩溃的编辑器」** 默认开启，可以关掉。

## 插件太旧或没装上时 Agent 自己处理

Agent 发现工程里的插件版本太旧、缺命令，或者根本没装上时，会调用 `project_update_plugin`，不再让你去设置里手动更新。这个工具需要你审批，做的事是：

1. 工程已经是最新插件时，什么都不动，也不关编辑器
2. 编辑器开着时，先检查有没有未保存的改动：有就拒绝并列出清单，请先保存
3. 关掉编辑器，安装对应版本的插件，从磁盘回读版本号写进回执
4. 编辑器原来开着的话，重新打开工程并等插件连回来；原来没开，只装插件，不替你打开编辑器

装不上时，回执第一句就是失败原因。你用「移除桥接插件」移除过的工程，默认不会被装回去。

插件连不上（编辑器卡死，或根本没装插件）时，盒子没有办法让编辑器正常退出。这时只有你明确同意丢弃未保存的改动，Agent 才会结束进程；否则它会请你自己保存并关掉编辑器。

## 常见情况

### 导入工程时提示插件没装上

提示里会写原因：

| 原因                          | 处理                                                                                 |
| ----------------------------- | ------------------------------------------------------------------------------------ |
| 这个 `.uproject` 没写引擎版本 | 缺 `EngineAssociation`。用 UE 正常打开一次工程通常会补上，也可以手动编辑 `.uproject` |
| 没有这个引擎版本的随包插件    | 引擎版本超出 5.0–5.8，或者你用的是自己构建的精简包                                   |
| 这个 `.uproject` 读不出来     | 文件可能已损坏，先确认它是完整的 JSON                                                |

弹窗标题是「工程已导入，但 AI 无法连接该引擎」，主按钮是「**交给 AI 排查**」：点它会新开一条对话，把工程路径和失败原因交给 Agent 去查。也可以事后从工程卡片右键 →「安装桥接插件」。

### 应用更新后，一批工程提示插件没能更新

应用升级后，所有工程的插件同时判为过期，失败往往是一批，提示按「N 个工程 + 第一条原因」汇总。这些工程还在用旧版插件，多数时候照常能用，但建议重装。

::: warning 重装前先关掉虚幻编辑器
文件被占用是头号失败原因。
:::

::: tip 「要不要重装」不只看版本号
两条都满足才算最新：版本号不低于随包版本，**并且**源码指纹一致。

只比版本号，会漏掉「插件源码改了但版本号没变」的情况，装过旧构建的用户就拿不到修复。所以版本号看起来没变，盒子也可能提示更新。
:::

### 装不上时不会写进 `.uproject`

安装失败时，`.uproject` 里不会留下指向它的条目。

这是有意的。留着一个指向缺失插件的条目，UE 启动时会报「找不到插件 X」并弹框问要不要禁用，生成工程文件或构建时直接失败。所以装不上就不写。

右键手动安装在报「成功」之前，也会回读一次插件文件是否真的在磁盘上。

### 清理旧版插件

早期版本会把插件装到**引擎目录**里。**设置 → 插件 → 清理旧版插件** 可以清掉这些残留。

同样需要**先关闭虚幻编辑器**，否则文件被占用会导致失败。提示会列出未能清理的引擎。

清理完会报「已清理 N 个引擎的残留插件」，一个都没有时报「未发现残留 UnrealAgentLink 插件」。

## 插件源码

设置 → 插件 → 「插件开源项目」可以打开源码地址，看代码和更新记录。

## UE 5.8 的额外能力

工程用 UE 5.8 或更高版本时，可以接入引擎官方的 MCP 工具集，见 [MCP · 虚幻引擎自带的工具集](/guide/mcp#虚幻引擎自带的工具集)。该工具集与 UnrealAgentLink 相互独立，可同时使用。
