# 虚幻盒子是什么

给一个目标，让 Agent 在你正在跑的虚幻工程里把活干完。

虚幻盒子是一个**直接操作虚幻编辑器的开源 AI Agent**。它是装在本机的桌面应用，给 Agent 配上工具、素材和权限，由 Agent 在真实的工程里放 Actor、改蓝图节点图、连材质、跑 PIE、编译 C++。改动直接落在工程里，不需要你复制代码再粘贴。

## 一轮任务长什么样

1. 你说一句：「把关卡里的 Actor 按类型归进大纲文件夹」。
2. Agent 自己挑工具、一步步调用，每次调用的工具名、参数、返回值都摊在对话里。
3. 常规操作直接执行；碰到风险操作，它停下来等你批准。
4. 干完之后，盒子列出这一轮改了什么，并回引擎重新读一遍，核对结果和 Agent 的说法是否一致。

## Agent 靠什么干活

**模型** —— 你自己配一家服务商。目录内置 87 项，其中 55 项是对话模型服务商：国际厂商、国内厂商、订阅账号和套餐，以及 Ollama、LM Studio 这类本机推理；其余是生图、语音、嵌入等专用接口。密钥加密存在本机，请求直达服务商，不经过我们的服务器。见[配置模型](/guide/ai-setup)。

**工具** —— 一次具体操作：放一个 Actor、读一份材质的节点图、编译一次 C++。内置一百多个，覆盖关卡、蓝图、材质、资产、几何体、动画、UMG、Sequencer、PCG、PIE 和 C++。见 [Agent 能做什么](/guide/capabilities)。

**技能** —— 一组做法说明，规定某类任务的处理流程、已知陷阱和不适用的场景。内置 27 个。你不需要指名，Agent 自己挑。见[工具、技能与权限](/guide/tools-and-skills)。

**权限** —— 权限档位决定它能动到哪儿、什么时候停下来问你，文件访问范围决定它能读写哪些目录。默认是「帮我批准」：它自己动手，只在识别到风险操作时停下来。见[审批模式](/guide/assistant#审批模式)。

**核对** —— 干完之后有三层：本轮改动列出净结果和 diff；「审查」用只读工具回引擎里重新读一遍；第三层要求 Agent 不凭记忆回答，每条都重新查询，再写出实际值。见[结果核对](/guide/assistant#结果核对-三层)。

## 它要接上虚幻编辑器才干得动活

Agent 的引擎类能力全部通过随包附带的 **UnrealAgentLink** 插件下发到正在运行的编辑器，支持 UE 5.0 至 5.8。

没连上时，这些工具不会交给 Agent。它会告诉你需要先打开工程，不会编造一个看起来成功的结果。资产库、蓝图库、材质库、笔记与知识库不依赖引擎，随时可用。

见[连接虚幻引擎](/guide/plugin)。

## 其余模块的位置

这些模块各自有完整的界面，可以单独使用。同时，它们给 Agent 提供作用目标、素材、参考资料和对外接口：

| 模块                   | 对 Agent 的作用                                                            |
| ---------------------- | -------------------------------------------------------------------------- |
| **项目库**             | 登记工程与引擎，确定 Agent 的作用目标                                      |
| **资产库**             | 素材来源。Agent 从中检索素材、导入工程，也向其中写入生成结果               |
| **蓝图库 / 材质库**    | 可复用片段的仓库。Agent 在处理同类任务时检索并参考其中的内容               |
| **笔记与知识库**       | 资料来源。Agent 针对绑定的知识库检索材料，也把研究结果写回去               |
| **AI 创作、3D 查看器** | 素材生成与检查                                                             |
| **命令行、MCP**        | 把这一百多个工具开放给脚本，以及 Codex、Claude Code、Cursor 这类外部客户端 |

## 开始之前

你需要自备两样东西：

- **虚幻引擎** —— 虚幻盒子不含引擎。连接插件支持 UE 5.0 至 5.8。
- **模型 API 密钥** —— 用 AI 功能时需要。不想掏密钥就用 Ollama、LM Studio 跑本机模型。模型必须支持工具调用，否则操作不了引擎。

不配模型也能用：资产库、蓝图库、材质库、笔记与知识库都是完整的独立工具。

### 平台

|         | 安装包   | 引擎发现               | 预编译连接插件       |
| ------- | -------- | ---------------------- | -------------------- |
| Windows | ✅       | ✅                     | ✅                   |
| macOS   | 源码构建 | ✅ 常见目录 + 手动添加 | 构建与发布验收未完成 |
| Linux   | 源码构建 | 尚未适配，需手动添加   | —                    |

**Windows 是主力平台**，功能都在这上面验证。Releases 只发布 Windows 安装包，macOS 和 Linux 需要从源码构建（见[安装与更新](/guide/install#从源码构建)）。macOS 还能检测运行中的 UE4 / UE5 编辑器及其工程路径。Linux 上 `uebox` 命令行暂不可用。Blender 互联管线支持 Windows 和 macOS，Linux 尚未适配。

## 开源版

本手册描述的是开源版，Apache-2.0 许可。

- **不需要账号。** 应用本身没有账号体系，也没有试用期。只有你给模型服务商选「用账号登录」时，才会打开浏览器授权。
- **本地功能不依赖网络。** 默认的联网只有检查更新，只查不下载，见[安装与更新](/guide/install)；自己打包且没填更新源的构建不发起更新请求。模板源未启用时不请求模板列表。
- **模型请求直达服务商。** 密钥加密保存在本机，不经过我们的服务器。
- **其余联网由你开启。** 联网检索、生图、网盘、团队资产服务器、对象存储，用到才连。
