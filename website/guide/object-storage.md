# 对象存储

接入你自己的云存储桶（兼容 S3 接口即可）。盒子里需要把文件传到云上、换成链接交给其他服务的功能，会使用这里配置的桶。

可选。不配的话，这些功能会退回各自的本地做法，不会报错。

配置入口：**设置 → 对象存储**。

## 哪些功能会用到

| 功能                                              | 用它做什么                                               |
| ------------------------------------------------- | -------------------------------------------------------- |
| [对话里的图片](/guide/assistant#附件)             | 拖进来的图传到桶里，模型凭链接看，不再把图片编码进请求   |
| [对话里的视频和音频](/guide/assistant#视频和音频) | 拖进来的音视频传到桶里，能看视频的模型凭链接直接看       |
| [AI 创作](/guide/aigc)                            | 视频生成用到本地参考视频或参考音频时，先传到桶里换成链接 |

桶配置一次，上面所有功能共用。以后有新功能用到它，会加到这张表里。

## 准备一个存储桶

支持任何兼容 S3 接口的对象存储。下面按服务商分别写。**只需要做一次。**

无论用哪家，最终需要拿到这五项信息：

| 要填的               | 是什么                                                   |
| -------------------- | -------------------------------------------------------- |
| **Region**           | 桶所在的地域                                             |
| **Bucket**           | 桶名                                                     |
| **AccessKey ID**     | 访问密钥的 ID                                            |
| **AccessKey Secret** | 访问密钥的密码                                           |
| **Endpoint**         | 服务地址。阿里云、腾讯云、AWS 会按 Region 自动算，不用填 |

::: warning 用子账号的密钥，别用主账号的
下面每一家都写了怎么建一个**只能读写这个桶**的子账号。主账号密钥能动你账号下的一切，泄露了代价很大。
:::

### 阿里云 OSS

**1. 建桶**

1. 打开 [OSS 控制台](https://oss.console.aliyun.com/)，点「创建 Bucket」
2. 名称随便起，比如 `my-uebox-media`
3. 地域选离你近的，比如「华东1（杭州）」。记下它的地域 ID，杭州是 `cn-hangzhou`、北京是 `cn-beijing`、上海是 `cn-shanghai`、深圳是 `cn-shenzhen`
4. **读写权限保持「私有」**。不需要公共读，原因见[私有桶别人读得到吗](#私有桶别人读得到吗)

**2. 建一个只能用这个桶的子账号**

1. 打开 [RAM 访问控制](https://ram.console.aliyun.com/users)，创建用户，勾选「使用永久 AccessKey 访问」
2. 创建完会显示 **AccessKey ID** 和 **AccessKey Secret**。Secret 只显示这一次，马上存好
3. 给这个用户授权。最省事的是系统策略 `AliyunOSSFullAccess`，但它能动你所有的桶。更稳妥的是新建一条自定义策略，只放开这个桶的这个前缀（把 `my-uebox-media` 换成你的桶名）：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["oss:PutObject", "oss:GetObject", "oss:DeleteObject"],
      "Resource": ["acs:oss:*:*:my-uebox-media/uebox-media/*"]
    },
    {
      "Effect": "Allow",
      "Action": ["oss:ListObjects"],
      "Resource": ["acs:oss:*:*:my-uebox-media"],
      "Condition": { "StringLike": { "oss:Prefix": ["uebox-media/*"] } }
    }
  ]
}
```

**3. 在盒子里填**

| 字段                  | 填什么                                             |
| --------------------- | -------------------------------------------------- |
| 服务商                | 阿里云 OSS                                         |
| Region                | `cn-hangzhou`（你的地域 ID，**不带** `oss-` 前缀） |
| Bucket                | `my-uebox-media`                                   |
| AccessKey ID / Secret | 上一步拿到的                                       |

Endpoint 会自动算成 `https://s3.oss-cn-hangzhou.aliyuncs.com`。注意是 `s3.oss-` 开头：这是 OSS 的 S3 兼容地址，控制台上显示的 `oss-cn-hangzhou.aliyuncs.com` 不认这套签名。

### 腾讯云 COS

**1. 建桶**

1. 打开 [COS 控制台](https://console.cloud.tencent.com/cos/bucket)，点「创建存储桶」
2. 名称填完后，控制台会自动在后面加上你的 APPID，完整桶名形如 `my-uebox-media-1250000000`。**填到盒子里的是这个完整名字**
3. 所属地域记下地域代码，广州是 `ap-guangzhou`、北京是 `ap-beijing`、上海是 `ap-shanghai`
4. 访问权限保持「私有读写」

**2. 建子用户**

1. 打开 [访问管理 CAM](https://console.cloud.tencent.com/cam)，新建子用户，访问方式勾「编程访问」
2. 授权时搜 `QcloudCOSDataFullControl`（数据读写），或者自己写一条只放开这个桶的策略
3. 拿到的 **SecretId** 填进 AccessKey ID，**SecretKey** 填进 AccessKey Secret

**3. 在盒子里填**

| 字段                  | 填什么                                           |
| --------------------- | ------------------------------------------------ |
| 服务商                | 腾讯云 COS                                       |
| Region                | `ap-guangzhou`                                   |
| Bucket                | `my-uebox-media-1250000000`（带 APPID 的完整名） |
| AccessKey ID / Secret | SecretId / SecretKey                             |

Endpoint 自动算成 `https://cos.ap-guangzhou.myqcloud.com`。

### Cloudflare R2

R2 **下行流量免费**。文件会被反复读取的话（见[费用](#费用)），R2 最省钱。

**1. 建桶**

1. Cloudflare 控制台 → R2 → Create bucket，名称比如 `uebox-media`
2. 记下 R2 首页右侧的 **Account ID**

**2. 建 API 令牌**

1. R2 首页 → Manage R2 API Tokens → Create API token
2. 权限选「Object Read & Write」，范围指定到刚建的桶
3. 创建后显示 **Access Key ID** 和 **Secret Access Key**，Secret 只显示一次

**3. 在盒子里填**

| 字段                  | 填什么                                               |
| --------------------- | ---------------------------------------------------- |
| 服务商                | Cloudflare R2                                        |
| Region                | `auto`                                               |
| Bucket                | `uebox-media`                                        |
| Endpoint              | `https://<你的 Account ID>.r2.cloudflarestorage.com` |
| AccessKey ID / Secret | 上一步拿到的                                         |

选 R2 时「路径式寻址」会自动打开，不用改。

### Amazon S3

1. S3 控制台建桶，保持「阻止所有公共访问」开着。记下地域代码，比如 `us-east-1`、`ap-southeast-1`
2. IAM 新建用户，附加一条只放开这个桶的策略（把 `my-uebox-media` 换成你的桶名）：

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject"],
      "Resource": "arn:aws:s3:::my-uebox-media/uebox-media/*"
    },
    {
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::my-uebox-media",
      "Condition": { "StringLike": { "s3:prefix": "uebox-media/*" } }
    }
  ]
}
```

3. 给这个用户创建访问密钥，填进盒子。Endpoint 自动算成 `https://s3.<地域>.amazonaws.com`

从国内的服务去读海外 S3 上的文件，可能很慢甚至超时。主要用国内服务的话，优先选阿里云或腾讯云。

### 自建 MinIO 或其他 S3 兼容服务

服务商选「MinIO」或「其他 S3 兼容服务」，Endpoint 自己填，不带桶名。MinIO 要打开「路径式寻址」。

::: danger 地址必须能从公网访问
存进桶里的文件，常常要由云端的服务（比如模型厂商）凭链接去读，而不是你的电脑。`127.0.0.1`、`localhost`、`192.168.x.x` 这类本机或内网地址，云端访问不到。测试连接时遇到这类地址会直接提示。
:::

## 在盒子里配置

1. **设置 → 对象存储**，打开「启用对象存储」
2. 选服务商，填 Region、Bucket、AccessKey ID、AccessKey Secret
3. 点「**测试连接**」，看到绿色的「连接正常」再往下走
4. 点「**保存**」

保存后，连接信息收成一行摘要（比如「阿里云 OSS · my-uebox-media（cn-hangzhou）」），下面显示已上传文件的数量和总大小。要改就点「修改」。

Secret 存在系统的安全存储里，保存后不再显示。之后修改连接时，Secret 那一栏**留空表示不改**。

### 测试连接做了什么

不只是「连得上」，而是把真实会用到的三步各走一遍：

1. 往前缀下写一个几十字节的测试文件
2. 用签名链接把它读回来，也就是云端服务读文件的方式
3. 删掉这个测试文件

三步都过才算通。常见的配错（密钥没有写权限、能写但链接读不回来）都会在这一步暴露。

### 高级设置

默认收起，大多数人用不到。

| 设置             | 默认                     | 什么时候改                                                                       |
| ---------------- | ------------------------ | -------------------------------------------------------------------------------- |
| **Endpoint**     | 按服务商和 Region 自动算 | 要走内网或加速域名时。通常不要改；改过的不会再被 Region 覆盖                     |
| **路径前缀**     | `uebox-media/`           | 桶里还放了别的东西，想换个目录。清理只动这个前缀下的文件；留空时只动盒子传的文件 |
| **公开访问域名** | 空                       | 你给桶绑了 CDN 或自定义域名，并且开了公共读。填了以后链接永不过期，对缓存最友好  |
| **路径式寻址**   | 按服务商预设             | MinIO、R2 要开；阿里云、腾讯云、AWS 要关                                         |

## 管理传上去的文件

配好以后，**设置 → 对象存储**下面显示已上传文件的数量和总大小。

| 操作     | 怎么做                                                                               |
| -------- | ------------------------------------------------------------------------------------ |
| 全删     | 「全部清理」                                                                         |
| 自动清理 | 「自动清理（天）」。每次启动盒子时删掉这么多天没再用到过的文件，默认 7 天，填 0 关闭 |
| 立即清理 | 「立即清理」，按上面的天数马上清一次                                                 |

所有删除都会先确认，而且**只动盒子自己传的文件**（路径前缀下的；前缀留空时只认盒子按内容哈希起名的那些），桶里别的东西不会碰。

删掉的文件如果还被某处引用着（比如一条旧对话里带过的视频），盒子会记得它已经清理掉了，不会再把一个打不开的链接交出去。

::: tip 在服务商那边再加一道保险
对象存储一般都支持「生命周期规则」，比如阿里云 OSS 的「基于最后一次修改时间的生命周期规则」。给 `uebox-media/` 前缀设一条「30 天后删除」，就算盒子很久没开，桶也不会一直涨。
:::

## 私有桶别人读得到吗

读得到，而且只能读到你交出去的那一个文件。

没填公开访问域名时，交出去的是**签名链接**：链接里带着用你的密钥算出的签名，7 天有效。拿到链接的一方只能下载**这一个文件**，别的文件看不到，也列不出桶里有什么。桶本身保持私有即可。

链接过期不会让功能失效。盒子记的是文件在桶里的位置，不是链接本身，每次要用时都会生成一个当前有效的链接。同一个 6 天周期里生成的链接逐字相同，这样对依赖请求内容缓存的服务（比如模型厂商的上下文缓存）也友好。

但有两种设置会挡住云端服务：

- **防盗链（Referer 白名单）**：对方的服务器不带你设的 Referer，会被拒绝
- **IP 白名单或 VPC 限制**：只允许特定 IP 访问的桶，外面的服务访问不了

## 费用

对象存储按服务商的价格计费，通常分三块：

| 费用         | 说明                                                                                                                               |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| **存储**     | 按存了多少 GB、存了多久算。开着自动清理的话基本可以忽略                                                                            |
| **请求次数** | 上传、列表、删除各算一次，量很小                                                                                                   |
| **下行流量** | **要留意这一项。**每次有服务凭链接读文件，都是一次公网下载。同一个文件被反复读，流量就反复算。具体每个功能读多少次，见各功能的说明 |

想省流量，用 **Cloudflare R2**，它的下行流量免费。

## 出问题了

### 测试连接报「SignatureDoesNotMatch」

签名对不上。按顺序检查：

1. AccessKey Secret 有没有多复制了空格或换行
2. Region 和桶实际所在的地域是否一致。阿里云填 `cn-hangzhou`，不是 `oss-cn-hangzhou`
3. 阿里云的 Endpoint 是不是 `s3.oss-` 开头。在高级设置里改过的话，改回自动算出的那个

### 「NoSuchBucket」

桶名写错，或者地域选错。腾讯云的桶名要带 `-APPID` 后缀。

### 「AccessDenied」

这对密钥没有这个桶的权限。子账号至少需要读、写、列举、删除四项，范围覆盖路径前缀。参考上面各家的策略示例。

### 「写入成功，但签名链接读不回来」

多半是 Region 填得和桶的实际地域不一致。对照控制台上桶的地域改过来再测。

### 「是本机或内网地址，从公网访问不到」

见[自建 MinIO](#自建-minio-或其他-s3-兼容服务)。云端服务要读得到，存储得有公网地址。

## 数据存在哪

| 文件                        | 内容                                                     |
| --------------------------- | -------------------------------------------------------- |
| `object-storage.json`       | 连接配置，不含 Secret                                    |
| `ai-provider-secrets.bin`   | Secret，和模型密钥存在同一个加密文件里                   |
| `object-storage-index.json` | 本机上传过哪些文件、原文件名是什么，以及哪些已经清理掉了 |

都在[应用数据目录](/guide/where-is-my-data#应用数据目录)下。换机器时 Secret 可能解不开，重新填一次即可。
