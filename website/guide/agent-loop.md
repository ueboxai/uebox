# 助手是怎么干活的

这一页讲 Agent 运行时的机制：一轮任务怎么推进、上下文怎么管、出问题时哪几道防线会拦住它。

知道这些不是使用的前提，但它能解释界面上那些一闪而过的提示 —— 「正在压缩上下文」「同一个调用连续失败」「AI 锁定了 3 个资产」分别意味着什么，以及为什么助手有时候会停下来交给你。

配置项见[工具、技能与权限](/guide/tools-and-skills)，界面操作见 [AI 会话](/guide/assistant)。

## 一轮任务的形状

发出一条消息后，助手在同一轮里反复「想 → 调工具 → 看结果 → 再想」，直到它认为可以作答。

**没有固定的步数上限。** 一轮可以是一次工具调用，也可以是几十次。结束由三件事决定：

| 结束方式       | 触发条件                       |
| -------------- | ------------------------------ |
| 正常收尾       | 模型不再调用工具，直接作答     |
| 上下文接近上限 | 先尝试压缩，压不动才停         |
| 你按了停止     | 当前这一步跑完即停，不留半截活 |

工具调用默认**并行**执行，同一时间可能有好几个在跑。少数工具标了串行（保存、编译、撤销、PIE、输入注入），因为并发跑它们会互相覆盖。

## 子任务

助手可以把一段界限清晰的工作交给一个**子任务**去做，界面上每一路占一张卡片。

派子任务的典型理由：

- 中间过程会产生大量噪声（翻遍几百个资产找符合条件的那几个），不想让它挤占主对话
- 需要反复迭代到某个硬性条件成立（蓝图改到编译通过）
- 需要几个独立视角（让三路分别审查同一张图）

子任务**继承当前对话的完整上下文**，不需要把背景重新讲一遍。它不能反过来向你提问 —— 需要你拍板的事只会出现在主对话里。

## 上下文与压缩

输入框附近的「上下文 X / Y」是这条会话已经占用的窗口比例。

**用满约 70% 时自动压缩**：把靠前的历史总结成一段摘要，最近几轮原样保留。摘要要求逐字保留已确认的资产路径、节点 id、已完成的操作及其结果、你明确表达过的偏好和约束；丢掉的是中间探索、被推翻的方案和重复调用。

::: tip 为什么是 70% 而不是更贴边
剩下的 30% 不是浪费。一次工具调用可能突然塞进两张截图，从 70% 一步跨过窗口上限 —— 那时压缩根本来不及跑，拿到的是服务商的硬报错，整轮作废。
:::

也可以用 `/compact` 手动压。压缩不可逆：压过的历史只剩摘要。

### 发出去之前还有一道闸

即便没触发压缩，单次请求也可能过大（读进来一张 3.5 MB 的贴图就够了）。请求发给服务商之前会按该服务商的上限核一遍，超了就把**最早的那几张图**换成一句占位文字。

这份删减只作用于发出去的那一份，本地存的对话一个字节都不动 —— 换一个上限更宽的模型，那些图照样回来。

## 目标模式

`/goal <目标>` 或输入框的「目标」按钮。普通对话里模型说完就算完；目标模式多一个**审计员**。

每当助手停下来不再调工具，会起一个独立的审计员子任务去复核，它给出三种裁决之一：

| 裁决        | 含义                           | 之后                 |
| ----------- | ------------------------------ | -------------------- |
| **PASS**    | 验过了，成立                   | 结束                 |
| **FAIL**    | 没做完或做错了，缺什么说得出来 | 把原话退回去，接着改 |
| **BLOCKED** | 审计员够不着要验的东西         | 第一轮就停，交给你   |

审计员**看不到助手的推理过程**，只拿到目标原文、助手的结束语和本轮改过哪些东西，然后自己去查。这是刻意的：让干活的那个判自己完没完成，它会顺着自己的结论走。

审计员手上是盒子里所有只查看、不改动的工具，外加编译蓝图、编译材质、跑 PIE 这三个。不联网、不开浏览器、不用第三方 MCP 工具，也不编译 C++（一次几分钟，留给助手自己做）。

每一轮的裁决和理由会按时间顺序插进对话里，所以它为什么还在跑是看得见的。

目标定下后一直挂在会话上，直到你在输入框上方点掉。期间你再说的话照样算数：「算了，改成红色」之后，审计员按改过的要求验，不会拿老目标把助手拽回去。助手需要你拍板时会弹提问卡片，不会自己猜着往下做。

::: warning 目标模式的四个代价

- **默认最多迭代 10 轮**，到顶就停下来交给你，不会无限跑下去。在 **设置 → AI 助手 →「目标模式最多几轮」** 里改，1–50，下一条消息生效。
- **复核会真的动手**：审计员可以编译蓝图、编译材质、跑一次 PIE。这些是你没发起的动作，一轮一次。
- **复核烧的 token 不计入上下文条**。那个数字只反映干活那一路。
- **只读档位下不进目标模式**。`/ask` 或会话本身挂在只读时，这一轮按普通对话跑完，界面会说明目标模式没生效。

:::

「验不了」和「没做到」是两回事。引擎没连上、目标交付的是一段回答而不是可查的状态 —— 这类情况判 `BLOCKED` 后第一轮就停，不会催满轮数再告诉你没做成。

## 四道护栏

### 撞墙熔断

同一个工具、一字不差的同一组参数，连续失败两次之后第三次会被拦下。

换参数重试不算撞墙（搜不到就换关键词是正常排查），成功一次即清零。这道防线针对的是模型改个无关紧要的措辞就重发同一个必然失败的调用、直到你手动打断的那种循环。

### 资产锁

助手动一个资产时会锁住它，状态栏显示「AI 锁定了 N 个资产」，点开能看到是哪些、被哪条会话锁着。旁边有**全部解锁**。

锁挡两件事：

- **另一条会话改同一个资产** —— 直接失败，不排队。失败的那一方会收到说明并换个活干，界面上也会提示一次。
- **你在虚幻编辑器里手动保存同一个资产** —— 保存被挡下。你的改动仍在编辑器内存里，解锁后照常能存。

::: tip 工程启用了版本控制时这一层不生效
只读位归 Perforce 之类的版本控制管。盒子不碰它，避免签出状态和磁盘对不上。
:::

### 助手自己那条撤销栈

助手在关卡里做的改动记在**一条独立的撤销栈**上，和你手动操作的撤销历史互不相干。所以「把 AI 这一轮做的全撤了」撤不到你自己的任何一步。

三条要知道的：

- 撤销只改内存，之后要保存才落盘。
- **资产级操作不在这条栈上** —— 导入、移动、删除资产和保存，引擎本身就不记进撤销缓冲。
- 你和助手改了同一个对象时，撤销助手那一步会把整个对象还原到它动手之前，你那次修改跟着没了。

批量搬迁另有一套账本，见[能力范围 · 撤销与回滚](/guide/capabilities#撤销与回滚)。

### 审批门

每一次会改动东西的调用都经过审批门，由会话的[审批模式](/guide/assistant#审批模式)决定是放行还是弹确认。

调整档位**当场生效**：被确认框拦住的时候去把档位调松，本轮就少弹框，不用等下一条消息。

少数操作**每次都要当场批准**，「本次会话都允许」对它们无效 —— 例如往网页里点击和输入，因为每次的参数不一样，而参数本身就是风险。

## 中断之后

对话逐轮落盘。应用被关掉、崩溃，或者工具执行到一半进程没了，重新打开后这条会话可以从断点接着跑，上下文不丢。

模型或服务商报错中止时，回复下方有「继续尝试」，走的是同一条续跑路径，不是重开一轮。

## 模型是按需切换的

会话的 Agent 模型是你选的那个。以下情况会临时改用别的模型，不改变你的选择：

| 情况                                  | 改用                       |
| ------------------------------------- | -------------------------- |
| 这一轮带了图片，而 Agent 模型看不懂图 | 「**视觉**」的默认模型     |
| 触发压缩（生成摘要）                  | 「**轻量任务**」的默认模型 |
| 生图、生视频、语音                    | 对应用途的默认模型         |

视觉那条只看**这一轮**带没带图，不看历史 —— 五轮之前那张图早就被回答过了，不会把整条会话永久钉在视觉模型上。

各用途的默认模型见[配置模型 · 默认模型](/guide/ai-setup#默认模型)。
