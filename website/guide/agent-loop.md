# 助手是怎么干活的

这一页讲 Agent 运行时的机制：一轮任务怎么推进、上下文怎么管、出问题时哪几道防护会拦住它。

不看这页也能用。它解释界面上的几类提示：「正在压缩上下文」、「AI 锁定了 3 个资产」、目标模式的复核结论，以及助手有时会停下来交给你的原因。

配置项见[工具、技能与权限](/guide/tools-and-skills)，界面操作见 [AI 对话](/guide/assistant)。

## 一轮任务的形状

发出一条消息后，助手在同一轮里反复执行「想 → 调工具 → 看结果 → 再想」，直到不再需要调工具、直接作答。

**没有固定的步数上限。** 一轮可以是一次工具调用，也可以是几十次。结束方式有三种：

| 结束方式       | 触发条件                       |
| -------------- | ------------------------------ |
| 正常收尾       | 模型不再调用工具，直接作答     |
| 上下文接近上限 | 先尝试压缩，压不动才停         |
| 你按了停止     | 当前这一步跑完即停，不留半截活 |

工具调用默认**并行**执行，同一时间可能有好几个在跑。会互相覆盖的工具标为串行，按顺序一个个执行：蓝图写入与编译、保存、撤销、新建或打开关卡、PIE、输入注入、C++ 编译、浏览器操作等。

一轮结束时，如果本轮改了 20 个以内的引擎资产且引擎在线，盒子自动做一次[引擎体检](/guide/assistant#第二层-引擎体检)。

## 子任务

助手可以把一段界限清晰的工作交给一个**子任务**，界面上每一路占一张卡片，点开能看到它走过的每一步。

派子任务的典型理由：

- 中间过程噪声很大（翻几百个资产找符合条件的几个），不想挤占主对话
- 需要反复迭代到某个硬性条件成立（蓝图改到编译通过）
- 需要几个独立视角（让三路分别审查同一张图）

子任务**继承当前对话的完整上下文**，不需要把背景重新讲一遍。它不能向你提问，需要你决定的事只会出现在主对话里。

## 上下文与压缩

输入框右侧圆环显示这条对话已占用的窗口比例，悬停看数字。

**用到约 85% 时自动压缩**：把靠前的历史总结成一段摘要，最近几轮原样保留。摘要要求逐字保留已确认存在和已确认不存在的资产路径、已创建节点的 id、已完成的操作及结果、你明确表达过的偏好和约束、未完成的待办；丢掉中间探索、被推翻的方案和重复调用。

摘要从约 60% 起在后台提前写，到 85% 时直接换上，所以压缩时界面通常不会停下来等。

::: tip 为什么留着 15% 的余量
一次工具调用可能同时塞进两张截图，一步越过窗口上限。那时压缩来不及跑，拿到的是服务商的硬报错，整轮作废。
:::

也可以手动压缩（点圆环，或输入 `/compact`）。压缩不可逆：压过的历史只剩摘要。

### 发出去之前还有一道闸

即使没触发压缩，单次请求也可能过大（读进来一张 3.5 MB 的贴图就够了）。请求发给服务商之前，盒子按该服务商的上限核一遍，超了就把**最早的几张图**换成一句占位文字。服务商曾经因为请求过大返回 413 时，盒子会按那次的实际大小调低这家的上限。

这份删减只作用于发出去的那一份，本地存的对话一个字节都不动。换一个上限更宽的模型，那些图照样回来。

## 目标模式

`/goal <目标>`。普通对话里模型说完就算完；目标模式在每次收尾时多一个**审计员**。

### 一次复核怎么走

助手停下来不再调工具时，盒子起一个独立的审计员子任务复核。

1. **第一次复核**，审计员把目标拆成带编号的清单。每条写明：要求是什么、出自目标的哪句话、怎么查。
2. **之后每轮**，审计员拿同一份清单逐条重查，不能删改合并条目。上一轮哪条通过了不告诉它，因为助手后来的改动可能把已通过的弄坏。
3. 每条判三种结果之一：

| 结果        | 含义                                   |
| ----------- | -------------------------------------- |
| **PASS**    | 查过了，成立，并写明查了什么、怎么查的 |
| **FAIL**    | 没做完或做错了，缺什么写得出来         |
| **BLOCKED** | 审计员手上没有任何工具能验证这一条     |

4. 汇总后的处理：

| 情况                     | 之后                                           |
| ------------------------ | ---------------------------------------------- |
| 所有条目 PASS            | 结束，提示「复核通过：N 条均已检查」           |
| 有 FAIL                  | 把未通过的条目退回助手，接着改                 |
| 没有 FAIL，但有 BLOCKED  | 停下交给你，列出无法验收的条目                 |
| 审计员漏查了清单里的某条 | 停下：没查的那条可能正是没做完的那条，不算通过 |
| 同一条连续两轮 FAIL      | 停下交给你                                     |
| 到达轮数上限             | 停下交给你                                     |
| 审计员的输出读不出裁决   | 停下并给出输出摘要，不当作 FAIL 继续转         |

每一轮的结论按时间顺序插入对话，所以它为什么还在跑是看得见的。

### 审计员看到什么、能用什么

审计员**看不到助手的推理过程**，只拿到目标原文、你在设定目标之后又发的消息、助手的结束语和本轮用过的改动类工具名，然后自己去查。让干活的那个判断自己完没完成，它会顺着自己的结论走。

审计要求包括：把结束语当作待核实的说法，不当作线索图；编译通过或运行无报错，要确认它覆盖了需求才算数；靠删掉或关掉需求里的东西换来的通过，判 FAIL；证据薄弱或间接的，视为未满足。

审计员的工具是盒子里所有只读工具，外加编译蓝图、编译材质、跑 PIE 三个。以下不给：联网和浏览器、第三方 MCP、子任务和技能加载、向你提问、按次计费的 AI 生成与分析、性能 trace。也不编译 C++（一次几分钟，留给助手自己做）。

### 目标的生命周期

目标定下后一直挂在对话上，显示在输入框上方，直到你点 × 取消。期间你再说的话照样算数：说「算了，改成红色」之后，清单作废并按新要求重拆，审计员以你最新的话为准。助手需要你决定时会弹提问卡片，不会自己猜着往下做。

::: warning 目标模式的四个代价

- **默认最多迭代 10 轮**，到顶就停下来交给你。在 **设置 → AI 助手 →「目标模式最大轮数」** 里改，范围 1–50，下一条消息起生效。
- **复核会真的动手**：审计员可以编译蓝图、编译材质、跑一次 PIE。这些是你没发起的动作，每轮一次。
- **复核消耗的 token 不计入上下文圆环**，圆环只反映干活那一路。
- **只读档位下不进目标模式**。这一轮按普通对话跑完，界面提示「只读模式下无法修改任何内容，目标无法达成」。

:::

「验不了」和「没做到」是两回事。引擎没连上、目标交付的是一段回答而不是可查的状态，这类情况判 BLOCKED，不会催到轮数上限再告诉你没做成。

## 经验

引擎工具报错之后又换了做法成功时，盒子把这对「报错 → 成功做法」记进原始账。对话结束后，**整理员**只根据这份原始账提炼经验，聊天内容不产生经验。原始账里没有「失败后又成功」的配对时不调用模型，不产生费用。每条经验写入前要对账：报错片段必须是原报错里逐字出现过的，做法必须是那次成功调用真做过的，对不上的丢弃。

之后同一个工具再报出相似的错，盒子把本工程的经验附在报错后面给助手看，最多三条，本工程的排在通用的前面。经验只在报错时出现，平时不占上下文。

- 经验按工程存放，也有适用于所有工程的通用层。
- 每条经验记录被提示几次、采纳几次、成功几次。盒子会随机留一小部分该提示的场合不给提示作对照，用对照结果淘汰没有帮助的经验。
- 经验只由整理员写入，助手本身对经验目录只读。

在 **设置 → 经验库** 查看、删除或撤销上次整理，开关见[自动记录做法](/guide/tools-and-skills#自动记录做法)。

## 四道防护

### 撞墙熔断

同一个工具、一字不差的同一组参数，连续失败两次之后，第三次会被拦下。

- 换参数重试不算（搜不到就换关键词是正常排查）。
- 成功一次清零。任何一次**成功的改动类调用**（改了文件、改了资产、跑了命令）也会清零全部失败计数，所以「改代码 → 编译 → 再改 → 再编译」不会被误拦。
- 编译、打包、试玩、截图、跑命令这类结果取决于工程当前状态的工具，阈值放宽到连续失败 5 次。

这道防护针对的是：模型只改个无关紧要的措辞，就把同一个必然失败的调用重发一遍，直到你手动打断。

### 资产锁

助手动一个资产时会锁住它，状态栏显示「AI 锁定了 N 个资产」，点开能看到是哪些、被哪条对话锁着。旁边有**全部解锁**。

锁挡的是**另一条对话改同一个资产**：直接失败，不排队。失败的一方会收到「{路径} 正被「{对话}」修改，本次未改动」，并换个活干。关卡里的 Actor 操作锁的是当前关卡。

**默认不会拦你在编辑器里手动保存。** 要拦的话，打开 **设置 → AI 助手 →「修改资产时设为只读」**：助手改资产期间，对应的 `.uasset` 被设为只读，防止你在编辑器里保存时覆盖它的改动，代价是这些资产在编辑器里暂时存不了盘。

::: tip 工程启用了版本控制时，只读这一层不生效
只读位归 Perforce 之类的版本控制管。盒子不碰它，避免签出状态和磁盘对不上。
:::

### 助手自己那条撤销栈

助手在关卡里做的改动记在**一条独立的撤销栈**上，和你手动操作的撤销历史互不相干。「把 AI 这一轮做的全撤了」撤不到你自己的任何一步。

三点要知道：

- 撤销只改内存，之后要保存才落盘。
- **资产级操作不在这条栈上**：导入、移动、删除资产和保存，引擎本身就不记进撤销缓冲。
- 你和助手改了同一个对象时，撤销助手那一步会把整个对象还原到它动手之前，你那次修改跟着没了。

批量搬迁另有一套账本，见[能力范围 · 撤销与回滚](/guide/capabilities#撤销与回滚)。

### 审批门

每一次会改动东西的调用都经过审批门，由对话的[审批模式](/guide/assistant#审批模式)决定放行还是弹确认。

- 调整档位**当场生效**：被确认框拦住的时候把档位调松，本轮就少弹框，不用等下一条消息。
- 「本对话内均允许」只在当前对话有效；「以后均允许」写入设置，对所有对话生效，在 设置 → AI 助手 中逐项移除。
- 少数操作**每次都要当场批准**，两个「允许」按钮对它们无效，例如往网页里点击和输入、连接第三方 MCP 服务。它们每次的参数不同，参数本身就是风险。选了「完全访问权限」后，网页点击和输入也不再弹确认。
- 写本地文件、新建工程、导入资产、撤销、素材库的可恢复删除、蓝图和材质删节点这类有事务或可恢复的操作，在「帮我批准」档不弹确认。带 force、overwrite 参数或本身不可撤销的操作仍会弹。

**你明确要求的事，助手会照做。** 技能里写的限制是默认做法，不是禁令：你坚持要做时，助手说明一次风险，得到明确同意后执行。被拒绝的操作，你再次要求时可以重试。

## 中断之后

对话逐轮落盘。应用被关掉、崩溃，或者工具执行到一半进程没了，重新打开后这条对话可以从断点接着跑，上下文不丢。

模型连接中断时有两层自动续跑：

- **默认**：任务因连接中断失败后，自动「继续尝试」最多 2 次，分别等 10 秒和 30 秒。鉴权、参数、上下文超长、限流这类重来结果也一样的错误，不自动重试。
- **设置 → AI 助手 →「自动断点续传」**（默认开）：中转服务不稳定时，每 60 秒自动从断点继续，连续失败满 30 分钟才报错。中途成功回过一次话，计时清零。失败的重试不保留在对话里。

续跑从最后一个工具结果往下接，做完的工具不会重跑。最终仍失败时，回复下方有「继续尝试」，走的是同一条续跑路径，不是重开一轮。

模型网关一直不返回响应头时，盒子会到点自动重发请求，不排队。

## 模型是按需切换的

对话的 Agent 模型是你选的那个，绑定在这条对话上：续跑和后台任务认回原模型，切换只影响当前对话和之后新建的对话。以下情况会临时改用别的模型，不改变你的选择：

| 情况                                  | 改用                       |
| ------------------------------------- | -------------------------- |
| 这一轮带了图片，而 Agent 模型看不懂图 | 「**视觉**」的默认模型     |
| 触发压缩（生成摘要）                  | 「**轻量任务**」的默认模型 |
| 生图、生视频、语音                    | 对应用途的默认模型         |

视觉那条只看**这一轮**带没带图，不看历史。五轮之前那张图早就被回答过了，不会把整条对话永久钉在视觉模型上。

各用途的默认模型见[配置模型 · 默认模型](/guide/ai-setup#默认模型)。
