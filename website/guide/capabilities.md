# 助手能做什么

按领域列出助手能做什么，以及每个领域做不到什么。边界写在每节末尾的提示框里。

助手的能力由两部分构成：

- **工具** —— 一次具体操作，例如放一个 Actor、读一份材质的节点图、把一段代码编译掉。内置两百多个，实际给到模型的数量随对话状态、工具开关和[工具搜索](/guide/tools-and-skills#工具搜索-beta)变化。
- **技能** —— 一组做法说明，规定某类任务的处理流程、已知陷阱和不适用的场景。内置 27 个。

不需要指名工具或技能，助手按任务内容选。

收紧可操作范围见[工具、技能与权限](/guide/tools-and-skills)，一轮任务怎么推进见[助手是怎么干活的](/guide/agent-loop)。

## 先看前提

多数能力要求工程在虚幻编辑器里打开、插件已连接，见[连接虚幻引擎](/guide/plugin)。

| 类别                   | 需要引擎 | 说明                                                       |
| ---------------------- | -------- | ---------------------------------------------------------- |
| 关卡、资产、蓝图、材质 | 是       | 全部通过插件下发到正在运行的编辑器                         |
| 几何体编辑             | 是       | 还需额外启用 `GeometryScripting` 插件，见[几何体](#几何体) |
| 运行时验证（PIE）      | 是       | 游戏必须真的跑起来                                         |
| C++ 编译               | 是       | 编译走编辑器的热重载或 Live Coding，必要时关编辑器完整重编 |
| 资产库、蓝图库、材质库 | 否       | 纯本地                                                     |
| 笔记与知识库           | 否       | 纯本地                                                     |
| 本机文件、命令行       | 否       | 受文件访问范围限制                                         |
| 联网检索、浏览器       | 否       |                                                            |
| 生图、生视频、生 3D    | 否       | 按次向所配置的服务商计费                                   |
| 工程库、模板创建工程   | 否       | 导入外部文件和往关卡里放东西才需要引擎                     |

::: tip 断开连接时它会明说
引擎工具在未连接时不会出现在助手手上，它会告诉你需要先打开工程，不会编造一个看起来成功的结果。
:::

::: tip 插件太旧或没装上
助手可以调用 `project_update_plugin`：关编辑器、安装插件、重新打开工程。每次需要你批准；你主动移除过插件的工程默认不装回去。
:::

## 关卡与场景

### 摆放与修改

放置、查询、移动、旋转、缩放、改参数、删除 Actor。可以一次动一个，也可以用**选择器**按类型、名称、标签、所在文件夹批量操作，还能按包围盒沿某个轴排开一批物体。

- 所有长度单位都是**厘米**，和引擎一致。
- 放东西到地面上时，助手先读目标网格的轴心（pivot）再算坐标，不假设轴心在底面中心。模块化套件的轴心位置各不相同，假设一次就会整批错位。
- 改完会重新读一遍场景核对，不以工具返回的「成功」为准。
- 删除 Actor 前先查关卡蓝图和其他 Actor 对它的引用。被引用的默认不删，列出引用方；确认后才强制删除。

### 大纲整理

把关卡里的 Actor 按类型或名称归进大纲视图的文件夹。只改组织结构，不移动 Actor 在世界里的位置。

### PCG 程序化散布

在地形上散布树木、石头、草、道具；从零创建 PCG 图、读回嵌套的 spawner 设置、重新连线，以及排查**产出 0 个实例**的原因。后者是 PCG 最常见的问题，有专门的诊断路径。

### 地形与 RVT

新建地形：给尺寸建平地，或者用一张高度图（16 位 PNG、.r16、.raw）建。地形只能按块取整，要 1000 米实际会是 1008 米，回报的是实际尺寸。World Partition 关卡会像编辑器一样切成流送代理。

给地形配颜色 RVT 和高度 RVT：建资产、挂到每一块地形、放体积罩住整块地形。RVT 没效果时，它能指出五项检查里哪一项没对上。项目设置里的虚拟纹理开关（改了要重启编辑器）和材质里的 RVT 输出节点只检查、不自动改。

还不能雕刻、刷材质图层，每边最多 8160 格。

### 关卡本身

新建关卡、打开关卡、保存关卡、查询世界由哪些关卡构成、开关子关卡的流送。

其中**新建、打开、改流送**标为不可撤销：换关卡会丢掉当前关卡里未保存的改动，所以无论哪个审批档位都会先问你。

::: warning 关卡与场景的边界

- 导入网格体本身属于内容浏览器，不在这一节。
- 优化分析、资产体积报告属于[工程体检](#工程体检与性能数据)。
- 「看起来不对」这类反馈，助手会去读实际数值来对照，但**判断构图和美术质量**不在能力范围内。

:::

## 资产与内容浏览器

### 导入

把外部文件（FBX、贴图、音频等）导入工程。

- FBX 可以按动画导入到现有骨架，也可以把骨骼网格绑到现有骨架上。
- 指定覆盖并点名目标时，直接以目标名导入，引擎就地替换现有资产，引用不会断。
- 贴图按命名认类型：`*_normal.png` 作法线贴图；ORM、ARM、RMA、MRA、Mask 这类合并贴图能识别；回执里带贴图设置和引擎的导入警告。
- 从素材库导入 `.uasset` 后，自动检查这批资产的资产指南（缺失的项目设置），没满足的连同依据写进回执，并可以在你同意后改项目设置。
- 导入到工程时，检查资产需要的插件，目标工程没开的列出来，确认后写进 `.uproject`。

::: warning 导入的连带产物容易被忽略
一次 FBX 导入常常不止产出一个网格，材质、贴图、骨架会一并生成。同名贴图在不同网格里会**互相静默覆盖**，助手会在导入后回读实际产出，不按请求的清单报数。
:::

### 查找与检查

按名称、类型、路径查找资产；读单个资产的详情、依赖、被谁引用；读引擎的消息日志。

路径格式是这一块最常见的出错点（`/Game/...` 包路径、磁盘路径、对象路径三种不能混用），所以助手先查到真实路径再动手，不凭记忆拼。

### 修改资产自身的设置

改 Nanite、碰撞复杂度，改贴图的 sRGB、压缩、最大尺寸、翻转绿通道，每项都从引擎读回确认。

网格可以生成 LOD（默认逐级减半）和简单碰撞（盒、球、胶囊、凸包分解）。导入的 LOD 默认保留，替换需要你同意。

### 数据表

读数据表的行；批量增、改、删、重命名行。列名按编辑器显示名认，写错会给出建议，枚举列列出可选值。

一批改动要么全部成功，要么整批还原，并且是助手撤销栈上的一步。从 CSV 或 JSON 导入的表，会回报源文件，提醒你先确认是否该改源文件。

### 重命名、搬迁与命名规范

批量重命名、在文件夹之间搬迁、按命名规范审计并批量改名、清理重定向器、把资产连同依赖迁移到另一个工程。

批量操作**一律先 dry-run**：先出一份「打算怎么改」的清单，确认后才执行。

::: warning 内容操作的边界

- 数据表的列属于行结构体，这里改不了；复合数据表也不能直接编辑，要改持有该行的父表。
- 迁移到另一个工程的文件**不可回滚**（那是一次跨工程拷贝）。
- `delete_broken` 删掉的重定向器不可恢复，账本只记录删了什么。
- 没有落盘的搬迁没有指纹，也就不能回滚。

:::

## 蓝图

### 建资产

创建蓝图资产：指定父类、附带组件及其相对变换和属性。

### 改逻辑

在已有蓝图里编辑逻辑图：节点、连线、引脚默认值、布局，**一次调用写入整张图**，不是一个节点一个节点地加。还能按编译报错反复修到编译通过。

- 事件图可以新建（此前只能新建函数图）。
- 可以读写别的蓝图的变量。
- 自定义事件可以设置 Server、Client、Multicast 复制。
- 大图自动分页读取。

### 动画蓝图

AnimGraph、状态机、状态内部、转换条件都能读写，每一页按路径定位（例如 `AnimGraph/Locomotion/Idle->Walk`）。状态机页上的节点是状态，连线是转换。也可以新建动画蓝图（父类 AnimInstance 加骨架）。

### 管成员

逻辑依赖的东西也归它管：变量及其细节面板行为（是否暴露给编辑、是否可在实例上改）、事件分发器、组件事件、函数参数、父类、网络复制设置。

### 改之前先查谁在用

改名、改签名、删成员之前，`blueprint_find_usages` 调用编辑器的「在所有蓝图中查找」，列出哪些蓝图用到这个名字，不加载蓝图。适用于蓝图自己的成员，也适用于 C++ 的 `UFUNCTION`、`UPROPERTY`。它按名字匹配，同名的别的成员也会命中；没有建索引的蓝图搜不到，结果里会说明。

::: warning 蓝图的边界

- **引脚名不能猜**，每个节点都不一样。助手先查节点签名再写图，所以写一张陌生的图会多花几次调用。
- 材质图和 Sequencer 不走这一节，各有各的工具。
- 写图是**整张图一次写入**，会覆盖目标图里已有的节点和连线。

:::

## 材质

创建主材质、改节点连接、编译、创建材质实例、应用到 Actor、查找被谁引用、清理无用节点、整理布局。编译回执带指令数、采样器数及其上限、静态开关。

**诊断**：材质显示不对、草是紫的、编译不过，各有各的排查路径。

规模化的三件事也在范围内：材质参数集合（全场景统一改雨天、改队伍配色）、材质函数（一串节点复用）、引用查找。

**Substrate**（UE 5.4+）：读写 Slab、FrontMaterial 以及分层、混合、涂层、绒毛、薄膜、彩色玻璃等节点，工程还没启用 Substrate 时可以切换过去。

::: warning 材质的一个静默失败
参数名**不做校验**。给一个拼错的参数名设值，会存下一条没人读的记录，然后报成功。助手只从 `material_create_instance` 返回的可用参数或材质详情里取参数名，不凭记忆写。但这仍是这一块最需要你回头核对的地方。
:::

## 几何体

通过 Geometry Script 修改网格数据本身：布尔并集与差集、平面切割、简化（减面）、重拓扑、补洞、焊接、UV 投影、生成碰撞，结果写回静态网格资产。

::: warning 几何体的四条前提

1. **`GeometryScripting` 插件默认不启用。** 助手会先检测，没启用时可以帮你启用，但**必须重启编辑器**才生效，重启这一步要你来做。
2. **执行期间编辑器是卡住的。** 脚本同步执行，上限五分钟。看起来没响应是正常的，不要中途重发。
3. **布尔运算前要确认网格封闭。** 不封闭时结果不可靠，引擎可能不报错。遇到这种情况助手会停下来说明，不会擅自把模型补成另一个样子。
4. **默认另存副本**，不覆盖原件。撤销不能当备份用。

减面之后 UV 是否保留接缝取决于方法和参数，需要另行检查。
:::

::: danger 交互式建模工具完全够不着
雕刻、PolyEdit、CubeGrid 这些 Modeling Mode 里的工具**没有任何脚本接口**，只吃鼠标输入。这类需求助手会说明要手工做，不会用 Python 凑一个近似的。
:::

## 动画

在骨架之间重定向身体动画、测量姿势（帧率、帧数、骨轨道、某个关节的角度）、写固定姿势、在编辑器里预览结果。认骨按骨骼角色匹配，Biped、Mixamo 等非 Manny 骨架也能用。

已有调好的 IK Retargeter 就直接用；没有时助手自动建源/目标 Rig、按同名严格映射并对齐姿势。

动画蓝图（状态机、转换条件）的编辑见[蓝图](#动画蓝图)。

::: warning 动画的边界

- 重定向和测量工具在 UE 5.5 编译和验收，低于 5.5 返回不支持。
- 不支持 Control Rig 编辑，也不做网格几何编辑。
- 链映射只管骨骼对应。脚不滑、手贴住道具需要 IK goal 或 solver，自动生成不保证满足。

:::

## UMG 界面

创建 Widget 蓝图、按锚点和尺寸放置控件、设置文本/颜色/数值、把控件暴露为变量供蓝图驱动、渲染一张预览图检查结果。预览按项目的 DPI 曲线缩放。

::: warning UMG 的边界
只做布局和属性，不编辑蓝图节点图（见[蓝图](#蓝图)）。`ue_playtest` 不能点击运行中游戏里的 UI 按钮，见[运行时验证](#运行时验证-pie)。
:::

## 镜头与成片

### Sequencer

由模型计算关键帧并写入 Level Sequence：环绕、推轨、跟随、八字、手持抖动、升降。

- **读与诊断**：读一条序列里有什么；诊断渲染输出为黑、播放无响应、轨道变红、绑定丢失；出片前体检；修复缺失的 Camera Cuts 轨道。
- **对比**：两条序列逐绑定对比，检查受保护的原件有没有被改、迁移后的角色有没有保留每个动画状态。
- **重新绑定**：把失效的 possessable 绑定改指向你点名的 Actor。同名 Actor 不止一个时不猜，列出候选问你。
- **出片**：用 Movie Render Queue 渲成序列帧（PNG、JPG、EXR、BMP），也可以合成 MP4（需要本机装 FFmpeg）。

::: warning Sequencer 的边界

- **渲染只在你要求时才做，每一次都弹出审批。** 助手不会主动渲。
- 焦距动画、重定时、批量改属性尚未实现。
- 新建相机时会把整个当前关卡存盘，你在这个关卡里别的未保存改动会一起落盘。

:::

### 白盒出概念图

框定镜头、截取视口画面，把该截图作为参考图交给生图模型。

::: danger 输出是生成的图片，不是引擎渲染结果
这条路产出的是一张**新生成的**图片。需要引擎真实渲染时，要求出片（Movie Render Queue）。措辞不明确时（例如「把这个场景渲染成成品」），助手会先确认你要的是哪一种。
:::

### 任务转视频

把当前这次对话和它的成果做成一段可继续编辑的本地视频（教程或宣传片），包含文案、分镜、配音和音乐。

## 运行时验证（PIE）

「编译通过」只说明语法对，不说明跑起来不出错。助手可以把当前关卡真的跑起来验一遍。

| 能做             | 说明                                                                                      |
| ---------------- | ----------------------------------------------------------------------------------------- |
| **跑一段 PIE**   | 默认跑 5 秒，上限 60 秒，回报这段时间的蓝图 PrintString 输出、运行时错误、收尾截图        |
| **抓多帧**       | 按时间顺序抓最多 36 帧，每 9 帧拼一张图，用来判断「动没动、第几秒变黑」这类时间上的事     |
| **发控制台命令** | 在指定时刻往游戏里发控制台命令，触发靠事件驱动的逻辑                                      |
| **多人**         | 监听服务器或独立服务器，最多 4 个玩家，用来验证复制和 RPC；不改你的 Play 设置             |
| **查键位**       | 读出此刻游戏里挂着的输入动作、值类型、触发器和修饰器                                      |
| **模拟操作**     | 按动作名触发，或走真人那条路按某个键                                                      |
| **自动试玩**     | `ue_autoplay`：机器人自己走、跳、把输入按一遍，找卡住、掉出世界、报错的位置（**实验性**） |

::: tip 两种模拟操作验的不是同一件事

- **按动作名**（`IA_Jump`）直接触发，稳定、不受窗口焦点影响，但它**绕开了键位映射**。就算这个工程根本没把跳跃绑到任何键上，这条路照样能让角色跳。所以它的成功不能说明「按键正常」。
- **按键**（`SpaceBar`）走视口 → 键位映射 → 动作的完整链路，才验得出键位有没有绑对。

:::

加按键映射不需要你去项目设置里点：`ue_input_add_mapping` 同时支持 Enhanced Input（加到指定的 Input Mapping Context，动作不存在就新建）和旧输入系统，写完读回确认。

试玩期间，游戏视口四周亮起呼吸光，表示画面正被盒子接管。

::: warning 自动试玩是实验性的

- 平地和导航网格走得到的目标比较可靠。要跳台阶、爬楼、跨沟的路线经常规划不出来或走到一半卡住，报告里的「没走到」先怀疑地形，不要直接判定逻辑有问题。
- 移动绕开键位映射，走得到不等于玩家按 W 走得到。
- 点菜单是直接触发按钮的 OnClicked，没经过屏幕命中测试，点得开不等于玩家点得到。名字带「删除」「重置」「退出」「购买」的按钮不点。
- 探索模式没有断言：报告只能说明这段时间没崩、没卡死、没掉出世界，不能说明某个功能正常。
- 游戏里按下的按钮是真的，会写存档、发网络请求的逻辑会真的执行。
- 「一句话目标」模式需要先配置判定模型，没配时会拒绝并建议改用探索或写死步骤。
  :::

::: warning 运行时验证的边界

- **`ue_playtest` 点不了游戏里的 UI 按钮。** 游戏视口里的 UMG 走另一套命中测试和输入模式。
- 游戏正开着菜单（UIOnly 模式）时，按动作名照样生效而真人按键完全无效。返回里会带警告，看到它就不能下「操作正常」的结论。
- **一张收尾截图看不出运行过程**，单帧里不含时间。要看过程用多帧。
- 截图默认只渲场景，**HUD、UMG 和屏幕上的 Print String 字不在里面**，图里没有界面不代表界面没显示。需要界面时把抓帧模式切到「窗口」，代价是编辑器面板一起进画面，窗口最小化就抓不到。
- **不做画面质量判断。** 判位置、判物体在不在、判材质颜色可以；判亮度、判过曝不行，截图的曝光和你屏幕上的差一档。
- **不做性能基准。** PIE 里的帧率受编辑器本身影响，测出来的数不能拿去调优，性能走[专门的采集](#工程体检与性能数据)。
- 不做通关、不做玩法评测，不判断「这个关卡好不好玩」，那是设计判断。

:::

## C++ 与编译

新建类、改已有的类：读源码 → 改 → 编译 → 按报错继续改，直到编译通过，然后热重载进正在运行的编辑器。也能改 `.Build.cs` 的模块依赖。

- **新建类**用引擎自己的类模板生成，`.generated.h`、模块 API 宏、父类模块依赖都和编辑器「新建 C++ 类」产出的一样，只写文件不编译。纯蓝图工程的第一个类也能建，会连带建好主模块。
- **编译**按改动选路：函数体改动走热重载或 Live Coding；增删改 `UPROPERTY`、`UFUNCTION`、`USTRUCT` 字段、换父类、改构造函数默认值这类结构改动，走**完整重编**：关编辑器 → 编译 → 重新打开工程并重连。有未保存的改动时会拒绝并列出清单，你同意丢弃才继续。
- 编译回执会列出自上次编译以来改过的反射头文件，供判断是否需要完整重编。
- 另有「只编游戏目标」的检查，不关编辑器，用来发现 Runtime 模块里误用编辑器 API 的问题。

::: warning C++ 的边界

- **走 Live Coding 时编译失败拿不到行号**，那些只显示在 Live Coding 控制台窗口里。助手会尝试从 UnrealBuildTool 日志读回，读不到时不会猜是哪一行错，而是改用完整重编拿全部诊断。
- 工程名不是合法的 C++ 标识符（中文、带横杠、数字开头）时无法建主模块，需要先改成英文名。
- 默认不改引擎自身源码（`Engine/Source`）。你要求时才改，改之前会先说明：安装版引擎改了源码也不会重新编译，源码版需要整个引擎重编，可能几十分钟到几小时。
- 安装 Visual Studio 和编译工具链需要你自己做。

:::

## 工程体检与性能数据

对整个工程或当前关卡做体积、性能、资产问题的审计，输出按优先级排序的报告，附具体修改建议。

| 能做               | 回答的问题                                                          |
| ------------------ | ------------------------------------------------------------------- |
| **全工程资产排行** | 哪些资产最占地方、三角面最多、贴图最大                              |
| **依赖体积图**     | 一个资产连同它的依赖一共多大                                        |
| **关卡资产统计**   | 这个网格在关卡里一共画了多少三角形（按资产聚合）                    |
| **灯光普查**       | 投影灯半径内有多少可移动物体、使用 WPO 的材质、Nanite 与实例数      |
| **优化审计**       | 贴图尺寸、LOD、碰撞、Nanite 等常见问题                              |
| **性能采集**       | 帧率统计、预热后再采样，以及抓一份 Unreal Insights trace 再分析     |
| **崩溃报告**       | 读最近的崩溃日志，附崩溃目录里的日志尾部，并区分崩溃与 ensure、卡顿 |

全工程排行**不加载任何资产**，走资产注册表的标签，所以默认扫整个 `/Game`，上万个资产也是几秒钟。三角面排行只排非 Nanite 资产，Nanite 单列。

性能排查时，助手可以用 `r.*` 和 `ShowFlag.*` 整类开关做减法定位瓶颈。它通过控制台命令改的这些设置会自动记账，结束前一键还原，避免退出 PIE 后设置残留、污染之后的采样。

::: warning 体检的边界

- **只输出报告，不修改它发现的资产。** 要动手是另一次明确的请求。
- 注册表标签是保存那一刻写进文件的。老引擎存过的资产可能缺某个标签，**字段缺失不等于 0**，报告里会区分这两种。

:::

## 编辑器检查与系统诊断

**看** —— 截取视口画面（可以只截一块区域，也可以带上编辑器界面，也可以测光）、读工程设置和 `.uproject` 元数据、查世界由哪些关卡构成、读写引擎配置值。

**跑** —— 在编辑器里执行控制台命令和 Python 脚本、读性能数据、查崩溃报告、查本地 ZenServer 缓存（命中率、占盘）、读编辑器健康数据（启动耗时、卡顿率、进 PIE 的耗时等）、启用或停用插件、必要时重启编辑器、手动触发一次垃圾回收。

**崩溃之后** —— Agent 操作期间编辑器崩溃时，盒子可以关掉崩溃报告窗口、备份未保存的自动存档、重新打开工程，并告诉正在等待的助手。开关在 设置 → 插件 →「允许 Agent 重开崩溃的编辑器」，默认开。手动操作期间的崩溃不处理，5 分钟内再次崩溃不再重开。

::: tip 「编辑器里好好的，一进游戏就不对」先查关卡构成
子关卡在编辑器视口里看得见，但可能根本没进这次的游戏世界。画面里少了背景、地面或光照而日志又干干净净时，这条排在第一位。
:::

::: warning 截图的两个前提

- 截图渲的是**场景**，默认不含界面。要看界面得显式要求。
- 截图自己渲一帧，曝光和你屏幕上的差一档。它能判位置和颜色，判不了亮度。

「允许编辑器截图」可以整体关掉，见[工具、技能与权限](/guide/tools-and-skills#全局-允许编辑器截图)。
:::

## 素材生产

### 生图

生成和编辑位图：概念图、贴图、海报、UI 草图、多版变体，支持参考图。产出保存进资产库的 `AIGC/图片`。见 [AI 创作](/guide/aigc)。

### 3D 生成

从文字或参考图生成 3D 模型，也可以对生成的模型自动绑骨。见 [3D 生成与查看器](/guide/model3d)。

### 视频与音乐

生成视频片段（支持参考视频和参考音频）、分析一段视频、合成配音、为任务成片生成配乐。

### AI 做 3D 资产（串联流程）

从一句描述或一张参考图出发，把上面几项串起来：

```
生图（概念图 + 互相一致的四视图）
   → image-to-3D（底模）
      → Geometry Script（基础清理）
         → Blender（复杂修形）
```

每一段结束后**对照参考图核对**再进入下一段，不连续迭代。

::: warning 这条流程的两个已知死穴

- **堆叠基本体做不出有机造型。** 需要有机形状时必须走生成加修形，不要指望拼方块。
- **第三轮之后越改越差。** 所以流程要求逐条对照参考图，不让助手自己一轮轮迭代下去。

:::

### Blender 互联

把 UE 的静态道具或建筑网格导出到 Blender，按参考图修形并做视觉质量检查，再把可编辑副本导回 UE。保留原始 UE 资产，存一份真实的 `work.blend` 源文件，后续修改更新同一个回传资产。

::: warning Blender 互联的边界
不支持骨骼角色、动画、整场景同步。**目前仅支持 Windows。**
:::

## 应用自身

### 资产库

检索和整理素材库：查找模型或贴图、读写备注和标签、在文件夹之间移动、新建/重命名/删除文件夹、删除或恢复条目、清理重复登记，以及把库里的资产导入 UE 工程。

作用对象是**素材库**，不是 UE 工程里的资产，两者是不同的东西。

::: tip 搜索默认只看当前库
助手默认只搜当前活跃的保管库。要同时搜其他保管库，打开 设置 → 资产库 →「跨库搜索」。写入始终只发生在当前活跃的库；切换保管库会改变整个视图，助手会先问你，除非你点过「本对话内均允许」。
:::

### 蓝图库与材质库

这两个库是助手的片段仓库，可以读也可以写：

| 能做         | 说明                                                               |
| ------------ | ------------------------------------------------------------------ |
| **检索片段** | 按名称、节点类型找库里存过的片段                                   |
| **存进库**   | 圈定工程里的几个节点存成一个片段，节点长什么样就存什么样           |
| **放进工程** | 把库里的片段粘进当前工程的一张**空图**里，然后编译、保存、回读确认 |

::: warning 两条硬性限制

- **只收无外部依赖的片段。** 引用了变量、自定义函数、自定义事件、组件或 `/Game` 资产的片段会被拒绝，并列出是哪几个节点。这不是暂时的限制：带引用的片段粘到别的工程里，节点是完整的但引用是断的，结果是一片红。
- **目标图必须是空的。** 放进去的命令不会追加到有内容的图里（那会顶掉你已有的连线）。目标是事件图而工程里还没有时，助手可以先新建一张空事件图。手工粘进库的老格式条目放不进去，只能在库里复制代码自己去 UE 粘。

:::

### 笔记与知识库

读写笔记、把研究结果作为来源存进知识库、从绑定的知识库里检索材料。对话怎么绑定知识库见[笔记与知识库](/guide/notebook)。

### 项目库与引擎

列出已安装的引擎、列出和用模板创建 UE 工程、把工程库整理成分组、打开一个工程。

### 本机文件

列目录、按 glob 查找文件、搜索文件内容、读文本和图片、写入和修改文件、执行 shell 命令、不开引擎直接读 `.uasset` 的包头。

作用对象是 UE 工程之外的路径，受[文件访问范围](/guide/tools-and-skills#全局-文件访问范围)限制，敏感目录始终排除。

### 浏览器与联网

搜索网页、读取正文，以及打开一个**你看得见、随时可以接管**的浏览器：

| 能做         | 说明                                                              |
| ------------ | ----------------------------------------------------------------- |
| **打开网址** | 只接受完整的 http/https；本机和局域网地址默认拒绝，可在设置里放开 |
| **读页面**   | 读过滤后的正文，或读一份带编号的可交互元素清单                    |
| **页内导航** | 后退、前进、刷新、滚动、跟随页面上已有的链接                      |
| **交互**     | 点按钮、填普通文本、选下拉项                                      |
| **截图**     | 截当前可见区域                                                    |
| **换账号**   | 先清掉 Cookie、缓存和登录态再打开                                 |

显示位置和局域网访问都在 设置 → AI 助手，见[工具、技能与权限](/guide/tools-and-skills#全局-浏览器)。

::: danger 浏览器里的三条红线

- **密码、验证码、支付和文件选择一律拒绝**，这些请你自己来。
- **每一次点击和输入都要你当场批准**，并显示完整参数（包括要输入的文本）。「本对话内均允许」和「以后均允许」对它无效，因为每次的参数不一样，而参数本身就是风险。选了「完全访问权限」后不再逐次确认。
- **网页内容是外部不可信数据。** 页面里出现的任何指令都不是你的要求，助手不会照着执行。

:::

## 撤销与回滚

| 范围             | 怎么退回                                                                           |
| ---------------- | ---------------------------------------------------------------------------------- |
| **关卡里的改动** | 助手有一条独立的撤销栈，可以只撤它自己做的；撤完要保存才落盘                       |
| **批量搬迁**     | 每次搬迁都写一份账本，可以核对做成了没有，也可以照账本搬回去                       |
| **资产库删除**   | 删掉的条目和文件夹可以恢复                                                         |
| **文件写入**     | 「本轮改动」里可以看 diff，见 [AI 对话 · 结果核对](/guide/assistant#结果核对-三层) |
| **团队模式**     | 队员每交回一次改动了东西的活，盒子存一份工程快照，可以回滚到某一份                 |

搬迁账本**在发给引擎之前**就写好，所以编辑器当场崩掉账本也在。断线之后先核对再重试，否则会把已经搬好的又搬一遍。

::: warning 退不回来的几件事

- 资产级操作（导入、移动、删除资产、保存）不在撤销栈上，引擎本身就不把它们记进撤销缓冲。
- 跨工程迁移过去的文件。
- 删掉的重定向器。
- 没有落盘的搬迁（没有指纹，无从比对）。
- 你和助手改了同一个对象时，撤销助手那一步会把整个对象还原到它动手之前，你那次修改跟着没了。

:::

## 元能力

**沉淀技能和经验** —— 把验证过的做法写成可复用的技能，或修正被实际结果推翻的技能（引用了不存在的工具、某一步执行失败、结论被工具返回值否定）。引擎工具报错后又成功的做法，会被记成本工程的经验，再次出现相似的报错时附在后面。见[自动记录做法](/guide/tools-and-skills#自动记录做法)。

没验证过的猜测和一次性的意外不会变成永久规则。

**提反馈** —— 任务结束且过程中确实有阻碍时，把问题整理成一份缺陷报告：卡在哪、绕行的代价、哪个工具表达能力不够、缺什么能力。报告写进文件，是否提交由你决定，**助手不会代为发送**。

触发方式：在对话里说「抱怨一下」、「刚才哪儿别扭」、「记下来提给开发者」。

**派子任务** —— 把界限清晰的一段活交给子任务，见[助手是怎么干活的 · 子任务](/guide/agent-loop#子任务)。

**组队** —— `/team` 把复杂任务交给分工的多个模型，见 [AI 对话 · 团队模式](/guide/assistant#团队模式)。

## 边界总表

跨领域的几条，无论问什么都成立：

| 边界                         | 具体是什么                                                     |
| ---------------------------- | -------------------------------------------------------------- |
| **交互式编辑器工具驱动不了** | 雕刻、PolyEdit、CubeGrid 等没有脚本接口，只吃鼠标输入          |
| **渲染只在你要求时才做**     | Sequencer 出片每一次都要你批准                                 |
| **默认不改引擎源码**         | 你要求时才改，且安装版引擎改了不会重新编译                     |
| **不做美术与设计判断**       | 能核实事实，不评价好不好看、好不好玩                           |
| **不拼凑**                   | 单个工具做不到的事，不会用别的工具硬凑一个近似的，它会说做不到 |
| **不代替你对外发送**         | 缺陷报告、网页上的提交动作、账号相关操作都停在你面前           |
| **Blender 管线不支持 Linux** | 支持 Windows 和 macOS                                          |
