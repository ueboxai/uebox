# 配置模型

接一家模型服务商，AI 功能才能用。应用不含模型，也没有中转服务器，密钥直连你选的那一家。

配置入口：**设置 → 模型**。

![设置 → 模型：左侧服务商列表，右侧模型与默认模型](/shots/settings-models.png)

## 先决定接哪家

目录共 87 项，其中 55 项是对话模型服务商，其余是生图、语音、嵌入等专用接口。不需要挨个看，按你的情况挑：

- **想让它真的操作虚幻引擎** —— 选一家国际或国内厂商的旗舰对话模型。硬条件只有一条：**这个模型必须支持工具调用**，上下文窗口还要装得下工具定义。不支持工具调用的模型只能聊天。
- **不想花钱，或者不想让数据出本机** —— 用「本机推理」一组（Ollama、LM Studio、llama.cpp），不需要密钥，Base URL 已预填（Ollama 是 `http://localhost:11434/v1`），但你得先自己把服务跑起来。效果和速度取决于你的硬件。
- **手里已经有会员或编程套餐**（ChatGPT、Kimi、CodeBuddy / WorkBuddy、ZCode、各家 Coding Plan 等）—— 看[订阅服务](#订阅服务)，用会员账号或套餐密钥，不用另外买 API 额度。先读那一节的合规提示。
- **公司有自建网关** —— 「自建网关」一组（LiteLLM、One API / New API、Cloudflare AI Gateway 等），或者用「自定义」条目填地址。

## 六步配完

1. 设置 → 模型 → **+ 添加服务商**
2. 从目录中选一家
3. 点「**去获取 API 密钥 ↗**」，在服务商网站创建密钥，粘贴到「API 密钥」
4. 点「**测试连接**」
5. 点「**保存**」
6. 在「**默认模型**」中，把「**对话**」指向刚配置的模型

页面上方「添加服务商，并选择『对话』默认模型后即可使用 AI」的提示消失，就是配好了。

带「可登录获取」标记的条目（Codex、Kimi Code、CodeBuddy / WorkBuddy、ZCode、OpenRouter）不用复制密钥：第 3 步改点「用 XX 账号登录」，在浏览器里完成授权，见[订阅服务](#订阅服务)。

## 服务商目录

「添加服务商」弹出的目录预置了 87 项，按用途分成 15 组。弹窗顶部按用途分五个标签（对话 / 生图与视频 / 语音 / 音乐与 3D / 检索与工具），搜索框同时搜厂商名和模型名；每一项的副标题标明「免配置」「可登录获取」或「需 API Key」。

| 分组                     | 数量 | 内容                                                                                             |
| ------------------------ | ---- | ------------------------------------------------------------------------------------------------ |
| **本机推理**             | 3    | Ollama、LM Studio、llama.cpp。不需要密钥。                                                       |
| **订阅服务**             | 14   | 会员账号登录，或各家 Coding Plan / Token Plan 的套餐密钥，见[订阅服务](#订阅服务)。              |
| **国内厂商**             | 12   | DeepSeek、通义千问、智谱、硅基流动、MiniMax、百度千帆、火山方舟等。                              |
| **国际厂商**             | 20   | OpenAI、Anthropic、Google、xAI、Mistral、Groq、Amazon Bedrock、Azure 等。                        |
| **自建网关**             | 6    | LiteLLM、One API / New API、OpenRouter、Vercel AI Gateway、OpenCode Zen、Cloudflare AI Gateway。 |
| **图片生成**             | 7    | 对应的生成接口。                                                                                 |
| **视频生成**             | 2    | 对应的生成接口。                                                                                 |
| **音乐生成**             | 3    | 对应的生成接口。                                                                                 |
| **3D 生成**              | 3    | 对应的生成接口。                                                                                 |
| **语音合成**             | 4    | 豆包 TTS 2.0、阿里云 Qwen-Audio、Fish Audio、本机语音合成。朗读回复使用。                        |
| **语音识别（听写）**     | 4    | 豆包 STT 2.0、阿里云 Qwen-Audio、硅基流动 SenseVoice、本机语音识别。语音热键听写使用。           |
| **实时语音（语音通话）** | 2    | 语音通话使用。                                                                                   |
| **嵌入（知识库检索）**   | 7    | 知识库检索索引使用。                                                                             |
| **网页检索**             | 3    | Jina、自建 SearXNG。不配置时使用内置浏览器。                                                     |
| **结构化判定**           | 1    | 可选，用于收紧 Agent 的护栏。不配置时功能不受影响。                                              |

目录是静态数据，打开它不会发起网络请求 —— 它是从 models.dev 生成的快照，随版本更新。

目录中没有的服务商，可以用「**自定义**」条目（「OpenAI / Anthropic 兼容」）：只要对方兼容这两种接口之一，填写地址即可。

同一家可以添加多次（官方 + 自建网关是常见需求），已添加过的条目只标「已添加」，不禁用。

::: tip 生成类的服务商为什么单独分组
绑给「生图」的模型走的是图片接口，不是对话接口。混在对话厂商里的话，添加完 OpenAI 会发现模型清单里一个能画图的都没有 —— 那份清单是按对话模型筛的。

每个生成类条目背后都有一个照着该厂商官方文档写的适配器，所以这几组不接受「有名就收录」。
:::

## 订阅服务

「订阅服务」这一组有两类条目，目的都是用你已有的会员或套餐，不另外买 API 额度。

**用账号登录**（点「用 XX 账号登录」，在浏览器里授权）：

| 条目                      | 授权方式                                                       |
| ------------------------- | -------------------------------------------------------------- |
| **Codex**                 | 浏览器授权，回调到本机固定端口                                 |
| **Kimi Code（会员）**     | 设备码：在浏览器里输入界面上显示的一串码，点击可复制           |
| **CodeBuddy / WorkBuddy** | 浏览器登录（扫码或账号），盒子等到你登录完成                   |
| **ZCode Coding Plan**     | 用 Z.ai 账号登录，也可以直接填订阅 JWT；令牌失效后需要重新登录 |

等待授权时可以点「等待浏览器授权… 点此取消」，同一时间只能进行一次登录。ZCode 需要先在 ZCode 官方授权并开通 Coding Plan；盒子只使用 ZCode 订阅，不会回退到普通 API 余额；平台要求重新验证时，先在 ZCode 完成验证再重试。

**填套餐密钥**：阿里云百炼、智谱、火山方舟、腾讯云、MiniMax、阶跃星辰、小米 MiMo 的 Coding Plan / Token Plan，以及 OpenCode Go。条目已预填套餐的接口地址，到服务商网站拿套餐专用密钥填进去即可。

OpenRouter 在「自建网关」组，同样支持账号登录。同组的 OpenCode Zen 用 API 密钥，只预置走 `chat/completions` 的模型。

::: warning 是否符合各家服务条款，要你自己判断
订阅通常面向官方客户端，API 才是给程序用的。各条的来源如实记在这里：

- **OpenRouter** —— 官方文档明确写给第三方应用的授权流程，无争议
- **Kimi** —— 授权用的开源包是 MoonshotAI 自己发布的，官方文档也说明第三方工具与 CLI 共享同一份会员额度
- **ChatGPT（Codex）** —— 参数取自 OpenAI 自家开源的 Codex CLI，客户端 id 和回调端口都是它的公开常量
- **CodeBuddy / WorkBuddy** —— 腾讯没有给会员开放 API。盒子按官方命令行工具的登录流程和请求头直连，腾讯改接口或升级客户端校验都可能让它失效，账号也可能因此受限
- **ZCode** —— 协议参考社区开源实现（maskeb34/zcode）

盒子不代表任何一家做出合规承诺。
:::

登录换回来的是**会过期的令牌**。Codex、Kimi、CodeBuddy 的令牌连同刷新令牌一起加密存在本机，按需续期；ZCode 没有刷新接口，失效后重新登录。OpenRouter 换回来的是永久密钥，当普通密钥存。

::: tip ChatGPT 订阅拉不到模型列表
那个接口不提供列表，提示为「ChatGPT 订阅接口不提供模型列表。可用型号见内置清单，或按官方公告手动填写。」
:::

### Box Plan

**设置 → 模型** 页顶部的 Box Plan 卡片，是虚幻盒子自己的订阅服务，不属于上面任何一类。点「连接」后在浏览器里核对确认码并点「允许」，随后选择交给套餐的角色（对话、嵌入、生图、视频、3D、音乐、语音等）。你手动配过的角色默认不勾选。

- 卡片显示「本月已用 N%」和重置日期；今日额度用完时显示恢复时间
- 套餐管理的角色标有「由 Box Plan 管理」
- 点「断开」后，这些角色恢复为接入前的设置，密钥在服务端吊销

## 密钥的三种填法

直接粘贴就行，这是默认做法。另外两种是给不想让密钥落到本机的人准备的：

| 写法           | 例子                | 说明                                     |
| -------------- | ------------------- | ---------------------------------------- |
| 直接填写       | `sk-xxxxxx`         | 加密保存在本机                           |
| 环境变量名     | `OPENAI_API_KEY`    | 从环境变量读取，密钥不写入应用的配置文件 |
| `!` 开头的命令 | `!op read op://...` | 执行该命令，取其输出作为密钥             |

应用没有中转服务器，密钥只用于直接连接你填的那个 API 地址。

提示「无法安全保存密钥，请通过环境变量提供密钥」时，说明你系统的加密存储不可用，改用后两种写法。

## 默认模型

不同功能各用各的模型，在「**默认模型**」里分别指定。只配「对话」就能开工，其余等用到了再说：

| 用途                      | 说明                         | 未配置时                                             |
| ------------------------- | ---------------------------- | ---------------------------------------------------- |
| **对话**                  | 助手和各处对话窗口的默认模型 | **AI 功能不可用**                                    |
| **Agent**                 | 处理多步任务                 | 使用「对话」模型                                     |
| **视觉**                  | 主模型不支持识图时使用       | 主模型也不支持则无法发送图片                         |
| **轻量任务**              | 总结、起标题、判断意图       | 使用「对话」或「Agent」模型                          |
| **嵌入**                  | 知识库检索索引               | 知识库检索不可用                                     |
| **生图**                  | AI 创作                      | 无法生成图片                                         |
| **视频 / 音乐 / 3D 生成** | 对应的生成能力               | 对应功能不可用；音乐缺省时成片不带配乐               |
| **语音合成**              | 朗读 AI 回复                 | 朗读不可用                                           |
| **语音识别**              | 语音热键听写                 | 回退到实时语音通道；绑定豆包实时语音时热键听写不可用 |
| **实时语音**              | 语音通话                     | 语音通话不可用                                       |
| **网页检索**              | 网页搜索                     | 使用内置浏览器                                       |
| **结构化判定**            | 可选，收紧 Agent 的护栏      | 功能不受影响                                         |

「对话」一行默认同时管 Agent、视觉、轻量任务，点「分别设置」才拆开。

每一项旁边的 `?` 图标里有更长的说明。没配的项界面会直接写出后果（「AI 创作出不了图」「知识库检索不可用」「图片请求会报错」），不用你自己推。

几条容易踩的：

- **更换嵌入模型会自动重建知识库索引**，库较大时需要等待。用 Ollama 的本地嵌入模型可以避免云端费用。
- **视频生成可能要数分钟，失败也可能扣费**，计费规则以服务商为准。3D 生成同理。
- **音乐生成的商用权限**以服务商套餐为准。
- **语音合成**要先添加对应的语音服务商、填语音控制台的 Key，再在这里选具体型号；音色在模型设置里改。本机运行的 Kokoro、CosyVoice 等 OpenAI 兼容服务选「本机语音合成」，不用填 Key，音色填它自己的音色名（如 Kokoro 的 `zf_xiaobei`）。Fish Audio 的音色填 fish.audio 音色页地址里的那串 ID，留空用它的默认音色。

::: tip 「对话」和「Agent」的分工
「对话」是各处对话窗口的默认模型，「Agent」处理多步任务。只配「对话」时 Agent 跟着用它。

要让 Agent 操作引擎，那个模型必须支持**工具调用**（见下）。
:::

### 每条对话记住自己的模型

对话发出第一条消息时，会记下当时使用的 Agent 模型。之后：

- 在这条对话里换模型，只改这一条对话和之后新对话的默认，其他已有对话不受影响
- 中断后续跑、后台任务沿用这条对话原来的模型
- 记下的模型如果已从设置里删除，这条对话退回全局默认

## 模型清单

每家预置的模型最多 12 个，且只收录 2026 年之后发布的对话模型。补充模型有两种方式：

- **导入模型…** —— 从服务商的接口拉取完整列表
- **+ 添加模型** —— 手动填写模型 ID

手动添加时需要确认「能力」选项：

- **视觉** = 图片输入、文字输出
- **视频** = 视频输入、文字输出
- **生图** = 文字输入、图片输出
- **工具** = Agent 是否能使用它。**不勾选则无法操作引擎**
- **推理** = 先思考再回答

「上下文与输出上限」通常留空（跟随内置数据）。本机模型或自建网关按实际支持的值填写 —— 这个值决定[上下文条](/guide/assistant#上下文窗口)的分母和压缩触发点，填错会让压缩来得太早或太晚。

::: warning 两种「拉不到列表」

- 「此服务商不支持获取模型列表，请按其文档填写模型 ID」 —— 生成类接口常见
- 「该协议没有通用的模型列表接口，请手动填写模型 ID」 —— 协议本身没有这个端点

两种都不是错误，手填模型 ID 即可。
:::

### 删除模型 vs 删除服务商

删除单个模型只是把它从该服务商的清单里移除，密钥和其余模型都不动，**点「保存」后生效**。

删除服务商会一并删掉它的密钥，并清空指向它的默认模型。删除前的确认框会提示有几个正在运行的对话用着它，这些对话下一次调用模型时会报错。

::: tip 离开页面前会拦一下
有未保存的修改时切走会弹「有未保存的修改」，可以保存并继续、丢弃改动或继续编辑。
:::

## 测试连接失败

| 提示                         | 原因                                       |
| ---------------------------- | ------------------------------------------ |
| 请求超时                     | 地址不可达，或需要代理                     |
| API 密钥无效或已失效         | 密钥填写错误或已过期                       |
| 密钥没有访问该模型的权限     | 账号未开通该模型                           |
| 模型不存在                   | 模型 ID 有误，可用「导入模型」拉取可用列表 |
| 触发限流或额度不足           | 服务商侧的额度问题                         |
| 请求被拒绝（400）            | 检查模型 ID、API 地址、接口协议            |
| 连不上该地址                 | 本机服务未启动，或地址有误                 |
| 厂商服务端返回错误           | 服务商侧的问题，稍后重试                   |
| 连接失败，但厂商没有给出原因 | 无法归因，界面会附上厂商返回的原文         |

::: warning 部分服务商不提供连接测试
生图、视频这类接口调用即产生费用，因此不提供测试，界面会显示「连接测试会产生生成费用，因此不提供；首次生成时会验证配置」。

**「跳过了」不等于「测通了」** —— 配置是否正确要到第一次生成时才能确认。
:::

## 配置文件在哪

页面底部有「配置文件」路径和「在文件夹中显示」。

密钥不在那份文件里 —— 直接填写的密钥走系统加密存储，另存一处；环境变量和命令这两种写法本来就只存了写法本身。存放位置见[文件都放在哪](/guide/where-is-my-data)。
